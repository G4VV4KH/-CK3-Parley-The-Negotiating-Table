#    THE OPENERS DO NOT DO THIS, deliberately: opening a panel and refreshing a
#    candidate pool changes what the player may CHOOSE, never what is on the table.

# WHY THE REPORTING WRAPPERS ARE WRITTEN OUT IN THIS FILE INSTEAD OF BEING CALLED
#-------------------------------------------------------------------------------------
# *** THIS FILE'S CHOICE WAS RIGHT AND V17 PROVED IT THE HARD WAY. ***
# The shipped gated entries USED to pair a `custom_description` row with a REPORTING
# WRAPPER trigger that carried its own reasons — tnt_vassal_p_toggle's is_valid was
# the model: one custom_description for the game rule, then a bare call to
# T15 tnt_vassal_available_trigger, which supplied nine specific reasons of its own.
# THAT MODEL WAS THE DEFECT the user reported four times. A BARE row — a call to one
# of our own scripted triggers with no enclosing custom_description — inside an
# is_valid that [TntTip(...)] reaches makes the engine's trigger-DESCRIPTION walker
# describe the NAME, and with no `common\trigger_localization\` entry for it (we ship
# no such folder) it RENDERS «<name> has no localization» into the tooltip instead of
# the reasons. V17 inlined T15's and T21's rows into the three offending is_valid
# blocks (tnt_20_scripted_guis.txt) and tombstoned both wrappers.
# SO THE RULE BELOW IS NOW GENERAL, not a local workaround: every row the engine must
# describe sits inside a custom_description, here and everywhere else on that path.
# The mechanical check is _docs\tools\tnt_bare_tooltip_row_check.ps1 (CLAUDE.md §6.11).
# ITEM 19 HAS NO SUCH WRAPPER AND MAY NOT GROW ONE IN ITS GATE FILE:
# tnt_42_people_gates.txt:69-74 states the rule in its own header — "PURITY. There is
# no custom_description and no custom_tooltip anywhere in this file, and none may be
# added" — because every one of those triggers is reached from an EFFECT's `limit`
# (the six fills, E34, and the four apply legs' re-validation), and a custom_description
# evaluated during tooltip generation prints itself into that tooltip. That is the D5
# class of defect and it is not hypothetical: the fills run inside
# tnt_open_window_effect, whose tooltip the player reads on every open.
# So each gated entry below wraps the PURE pair gate in its own custom_description
# here, in a file no effect's limit can ever reach. This is the only shape available,
# and it is the shape tnt_pick_title_p_open already uses (tnt_21_pickers.txt:85-90).
#
# COST. Six openers and two toggles are bound with `enabled = "[TntValid(...)]"` plus

# GROUP A — THE SIX PANEL OPENERS
#
# Shape, verbatim from the shipped openers (tnt_21_pickers.txt GROUP C and
# tnt_22b_multiselect.txt GROUP A): write tnt_picker = <index>, write tnt_picker_side
# (0 = _p, 1 = _r), then rebuild this side's candidate pool. The panel appears because
# its `visible` matches those two numbers; no GetScriptedGui is called from any
# visible anywhere (Law R11).
#
# THE FILL IS NOT OPTIONAL. A picker panel's datamodel is a saved VARIABLE LIST, not a
# live query — `datamodel = "[TntList('tnt_list_hostage_p')]"` — so without the fill
# the panel would show whatever the pool looked like when the window opened, and a
# child who has since married or travelled would still be offered. The six fills are
# tnt_3a_people.txt P1-P6 and each opens with clear_variable_list, so calling one is
# always a full rebuild and never an append.
#
# THE TWO COURTIER OPENERS ALSO PRUNE, and the order fill-then-prune is the invariant,
# not a preference: the fill rebuilds the AVAILABLE list from every_courtier, which
# puts the already-chosen courtiers straight back among the candidates, and the prune
# takes them out again. tnt_35_multiselect.txt:241-243 states the pair for all six
# shipped openers and :306-313 carries the courtier lines in the refill-everything
# path for the identical reason. In a two-list panel a row's COLUMN is its selection
# state (there is no membership datafunction), so a courtier visible in both columns
# is not cosmetic — it is a row that lies about the offer.
#
# THE NAME tnt_multi_courtier_<side>_open IS THE GUI'S, and the distinction from the
# tnt_pick_ form is load-bearing rather than stylistic: gui\tnt_panel_people.gui:70-79
# flagged that the contract's register lists courtier add/remove/clear but no opener,
# chose this name from the shipped precedent (tnt_multi_title_p_open, and
# tnt_multi_prisoner_p_open, since RETIRED with its term) and gave that same prune
# argument. The window then bound
# it at :1447, :1455 and :2401, :2409. The name is settled by those five call sites.
#
# GATED, AND REFUSING AN OPENER STRANDS NOTHING. If the pair gate turns false while a
# hostage is already chosen, the "Choose..." button greys out — but the row's little X
# calls a group C entry, which carries no gate at all, so the term can always still be
# taken off the table. That division is the whole reason the clears are separate
# entries instead of a second branch of the opener.

# 16 / side 0 — the hostage the PLAYER sends into the PARTNER's keeping.
# Gate P2: tnt_can_hostage_trigger = { SENDER WARDEN }, the pair-level half of the
# hostage rules (both alive, neither a theocracy, the warden a real ruler above
# barony tier, not at war, and the warden not already holding a hostage from this
# court). The candidate-level half is P1 and it is inside the fill, which is why this
# is_valid does not repeat it.
tnt_pick_hostage_p_open = {
	scope = character

	is_valid = {
		custom_tooltip = {
			text = tnt_err_hostage_p_unavailable
			tnt_can_hostage_trigger = {
				SENDER = root
				WARDEN = var:tnt_partner
			}
		}
	}

	effect = {
		set_variable = {
			name = tnt_picker
			value = 16
		}
		set_variable = {
			name = tnt_picker_side
			value = 0
		}
		tnt_fill_hostage_p_effect = yes
	}
}

# HOW THE CLICKED ROW GETS HERE, and it is the one mechanism in this file that cannot
# be guessed: the panel's row calls `onclick = "[TntPickChar('tnt_pick_hostage_p_set')]"`
# (gui\tnt_panel_people.gui:148, :202, :269, :323), the TntPickChar macro performs
# exactly ONE .AddScope('tnt_picked', Character.MakeScope), and the entry declares
# `saved_scopes = { tnt_picked }` to receive it. One AddScope, never two chained —
# tnt_21_pickers.txt:20-22 records that two chained AddScope calls are unverified
# anywhere and must never be written. This is the same declaration the prisoner family
# made (tnt_22b_multiselect.txt, now commented out with that RETIRED term — the
# argument stands, only the example is retired).
#
# `exists = scope:tnt_picked` guards every body: the character may have died between
# the row being laid out and the click landing, and a GUI-supplied scope is exactly
# what report 02 §2.3 says to guard.
#
# THE UNIQUENESS TEST IS THE REASON THESE ARE NOT THREE-LINE CLONES. P16
# tnt_person_unique_trigger (tnt_42_people_gates.txt:1126-1155) states the law "one
# body may appear in at most one people-term of one treaty", and its header names this
# file's setters as its first caller. It is needed because the pools OVERLAP by
# construction — a grown son is both a hostage candidate and a courtier candidate
# (and until V16 a young son was both a hostage and a ward candidate; the ward rows of
# P16 are retired with the family, the hostage/courtier overlap alone keeps P16
# mandatory) — and no candidate trigger can see the
# other terms' picks, since a candidate trigger runs in the CANDIDATE's scope while
# the picks live on the player. It is called here in the PLAYER's scope with
# WHO = scope:tnt_picked, which is the only scope its `var:tnt_hostage_p` rows read
# correctly.
#
# IT IS IN THE EFFECT'S `limit`, NOT IN is_valid, and that is deliberate twice over:
#   * P16 is PURE — the whole of tnt_42_people_gates.txt is, by its own header rule —
#     so an effect's limit may reach it without any risk of a custom_description
#     printing itself into the confirm tooltip;
#   * whether a saved_scope is visible to is_valid at Execute time is not proven
#     anywhere in this mod, and a gate that silently never fires is worse than no gate.
# A refused pick is a SILENT no-op. That is the shipped answer for the same situation
# elsewhere (tnt_22b_multiselect.txt:244-249 on the cap: "a click at the cap is a
# silent no-op, and that is deliberate"), because these rows carry no `enabled` and no
# TntTip binding and there is nowhere for a reason to be shown — Law R11 forbids
# adding one per row.
#
# THE CANDIDATE TRIGGER IS *NOT* RE-TESTED HERE, on purpose. It would have to be asked
# inside `scope:tnt_picked = { … }`, and a bare `var:tnt_partner` inside that block
# reads the CANDIDATE's variable, not the player's — a silent wrong answer, and the
# very trap tnt_42_people_gates.txt:1210-1213 documents for the same shape. The list
# was rebuilt by the opener one click earlier, and the apply legs re-validate every
# person against the same trigger that built the list (tnt_3a_people.txt:447-451,
# :532-535), which is where staleness is actually caught.
#
# `remove_variable = tnt_picker` closes the panel and is OUTSIDE the guard, exactly as
# in all eight shipped setters: one pick is the whole interaction here (unlike a
# multi-select panel, which must stay open). tnt_picker_side is left alone — harmless
# residue, overwritten by the next opener, removed by tnt_picker_close and by
# tnt_reset_offer_effect.
######################################################################################

tnt_pick_hostage_p_set = {

	saved_scopes = { tnt_picked }

	scope = character
	saved_scopes = { tnt_picked }

	effect = {
		if = {
			limit = {
				exists = scope:tnt_picked

				# One body, one term — and this also IS the duplicate guard.
				# (The cap of three stood here and is RETIRED — see the group header.)
				tnt_person_unique_trigger = { WHO = scope:tnt_picked }
			}

			add_to_variable_list = {
				name = tnt_sel_courtier_p
				target = scope:tnt_picked
			}

			# The other half of the MOVE: out of the AVAILABLE column, so the row's
			# column keeps telling the truth about the offer. Guarded so that nothing is
			# asked of a list that does not exist and a candidate who is somehow already
			# gone from it is simply left alone.
			if = {
				limit = {
					has_variable_list = tnt_list_courtier_p
					is_target_in_variable_list = {
						name = tnt_list_courtier_p
						target = scope:tnt_picked
					}
				}
				remove_list_variable = {
					name = tnt_list_courtier_p
					target = scope:tnt_picked
				}
			}

			remove_variable = tnt_ab_state
		}

	}

# DIRECTION, and it may not be inverted: _p is the PLAYER, as liege, releasing the

# it, tnt_val_indep_p_value prices the player letting go of a vassal, and
# tnt_exec_indep_effect is called { SIDE = p  LIEGE = the player  VASSAL = the partner }.
# Inverting the gate would not error — it would price the wrong man's loss and free
# nobody.
#
# THE VALUE IS THE LITERAL 1 BECAUSE THE APPLY LEG TESTS `> 0`
# (tnt_3a_people.txt:608-609) and so does the price (tnt_58_person_values.txt:208, :228).
# A bare `set_variable = { name = X }` with no value would satisfy `exists` and fail
# `> 0`: a term that shows on the sheet, is priced at nothing and frees nobody.
#
# TWO is_valid ROWS, AND A trigger_if AROUND BOTH OF THEM — THIS IS WHERE LAW 1 IS
# OBEYED BY A TOGGLE.
#   * The gate rows: the Tier-4 game rule (P14/P15 read `exists = var:tnt_advanced`,
#     the answer E1 caches once per window opening at tnt_30_effects.txt:173-176 —
#     `limit = { tnt_advanced_terms_trigger = yes }`, a map lookup here rather than a
#     trigger tree per layout pass — because independence is
#     the exact inverse of the fealty term and a campaign that switched the dangerous
#     terms off but could still hand out independence would be incoherent) and the
#     CACHED answer to P13 tnt_can_release_trigger — vanilla's own
#     grant_independence rules, of which the de jure clause and "the liege is not at
#     war" are the two that most often say no. The cache (tnt_indep_ok_p/_r, written
#     by E33 once per open/refresh) replaced the live call after the 85,778-error
#     measurement — see the toggles' own comment boxes; the rules CAN turn false
#     while the window is open, which is why the switch-ON effect keeps one live
#     re-check even though the per-frame is_valid may not.
#   * The trigger_if: they apply ONLY when the term is not already on the table. A
#     trigger_if whose limit fails simply does not apply — the bare form
#     tnt_person_unique_trigger relies on for exactly this kind of "the question does
#     not arise" row (tnt_42_people_gates.txt:1111-1117) — so once tnt_indep_p exists,
#     is_valid is vacuously true, `enabled` stays on, and the player can always untick
#     what he ticked. Without it a liege who went to war after ticking the box would be
#     unable to withdraw the term and unable to send the offer either, since the send
#     gate re-tests it. That is the dead-click the hook zeroers were written to end
#     (tnt_22c_hooks_contracts.txt:711-724), reached here without a second entry
#     because the window gives this row one control, not a control plus an X.
#     A trigger_if/trigger_else pair inside a scripted_gui's is_valid is not novel: the
#     shipped fealty toggle carried one until the T15 wrapper absorbed it
#     (tnt_20_scripted_guis.txt:920-925).
#
# THE `else` BRANCH RE-TESTS THE GATE — layer 2 of the three-layer arrangement
# tnt_22c_hooks_contracts.txt:28-42 sets out, and its reason applies verbatim here: it
# is not established that Execute consults is_valid at all, so the write itself must
# refuse. Switching OFF carries no such test, by the same file's rule.
#
# NOTHING IS CLEARED ON THE OTHER SIDE. tnt_vassal_p_toggle drops tnt_vassal_r when it
# turns itself on, but that is one term's two directions; independence and fealty are
# two different terms, and C5 forbids only their COMBINATION. That combination is
# refused on the send path by tnt_no_indep_and_vassal_trigger (P17) and ordered
# defensively at apply time, so a toggle here that silently deleted a fealty term the
# player had composed would be doing another row's job behind his back.
######################################################################################

tnt_indep_p_toggle = {
	scope = character

	# NESTING: custom_description OUTSIDE, trigger_if INSIDE — and that order is
	# the correction, not a preference. The first draft put trigger_if outside so
	# that a ticked term could always be unticked, citing
	# tnt_20_scripted_guis.txt:920-925 as precedent; that passage documents the
	# REMOVAL of exactly such a construct ("the build-1 outer trigger_if/
	# trigger_else pair is gone"). The shape the mod actually ships live is this
	# one — tnt_20_scripted_guis.txt:1269-1285 and :1290-1307. Third ref dropped 08-24.
	# It also fixes a visible defect the other order caused: with the rows inside
	# the trigger_if, a ticked term left is_valid with NO rows at all, so the
	# window's `tooltip = "[TntTip('tnt_indep_p_toggle')]"` built an EMPTY tooltip
	# on a row that binds one. Here each row is always present and simply passes
	# vacuously once the term is on the table, so unticking can never be refused
	# and the tooltip always has something to say.
	#
	# *** THE SECOND ROW READS THE E33 CACHE, NOT THE TRIGGER — LOAD-BEARING,
	# *** 85,778 ERRORS MEASURED. *** This is_valid is bound as `enabled` and
	# re-evaluated on every layout pass; when it called tnt_can_release_trigger
	# directly it ran an any_vassal_or_below walk per frame AND handed the walk
	# `var:tnt_partner`, which the walk re-resolved against each vassal — the
	# fresh playtest log holds 85,778 script errors, every single one from this
	# entry's old line (tnt_24_people.txt:877 -> the walk in
	# tnt_42_people_gates.txt). tnt_indep_ok_p is P13's answer evaluated ONCE by
	# E33 (tnt_30_effects.txt) at window open/refresh, where the partner exists
	# by construction — the exact fix the file header's COST paragraph had
	# pre-registered. exists-then-value, ordered by the inner trigger_if's limit,
	# so an absent cache is a silent "no" and never a fetch (Law R13).
	is_valid = {
		custom_tooltip = {
			text = tnt_err_advanced_off
			trigger_if = {
				limit = { NOT = { exists = var:tnt_indep_p } }
				exists = var:tnt_advanced
			}
		}
		custom_tooltip = {
			text = tnt_err_indep_p_unavailable
			trigger_if = {
				limit = { NOT = { exists = var:tnt_indep_p } }
				trigger_if = {
					limit = { exists = var:tnt_indep_ok_p }
					var:tnt_indep_ok_p = 1
				}
				trigger_else = { always = no }
			}
		}
		# AGOT SUSPENDED (CK3 1.20): Watch-only validation tooltip parked; awaiting the AGOT update.
		# V14, USER ITEM 1: NAME THE REAL REASON. P13 now refuses a Night's
		# Watch pair (tnt_42_people_gates.txt, the T46 call), so the cache row
		# above already goes to 0 on its own and this toggle dies without any
		# edit here - but it would report "they are not your vassal" about a man
		# who plainly is. This row says what actually happened.
		# LEGAL IN A PER-FRAME is_valid: government_has_flag and has_variable on
		# a culture are FLAT reads on the character's government / culture
		# object - no iteration, no script value, no walk. That is precisely the
		# distinction the 85,778-error note above turns on, and this row is on
		# the right side of it.
		# The inner exists guard makes the row pass VACUOUSLY when there is no
		# partner, which is the shape tnt_42_people_gates.txt:1137-1143
		# prescribes for this file. In a vanilla game it is always true.
		# custom_tooltip = {
			# text = tnt_err_vassal_wall
			# trigger_if = {

		}
