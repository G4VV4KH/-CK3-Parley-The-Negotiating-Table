# PARLEY: THE NEGOTIATING TABLE - AI TELEMETRY, THE LOGGING HELPERS
#
# Reader's guide: _docs\91-AI-TELEMETRY-FORMAT.md. READ THAT FIRST if you are
# here to analyse a log rather than to edit this file.
#
# ASCII ONLY IN THIS FILE, for the same reason tnt_37_ai_offer.txt gives: the
# BOM stays the only non-ASCII byte, so no tool in the chain can turn a dash
# into mojibake INSIDE A STRING THAT IS WRITTEN TO A LOG AND THEN PARSED.
#
#=======================================================================
# STEP ONE, ANSWERED: HOW A CK3 MOD WRITES A LINE TO A LOG
#=======================================================================
# THE EFFECT IS `error_log`. Not debug_log. Every claim below is a measurement
# against this install, not a recollection.
#
# 1. IT EXISTS AND IT IS A REAL SCRIPT EFFECT. 16 vanilla call sites, e.g.
#      GAME\common\character_interactions\00_tributary_interactions.txt:2958
#      GAME\common\scripted_effects\00_romance_effects.txt:374, :395, :412
#      GAME\common\legends\legend_types\00_legends.txt:534
#      GAME\events\dlc\ep2\wedding_events\ep2_wedding_events.txt:1282
#    The engine string table also carries the sibling triads
#    error_log_scopes / error_log_stack_trace, info_log / info_log_scopes /
#    info_log_stack_trace and debug_log / debug_log_scopes / debug_log_date /
#    debug_log_details / debug_log_stack_trace. info_log has ZERO call sites
#    anywhere in the install and is therefore NOT used here (R2).
#
# 2. *** IT INTERPOLATES, INLINE, WITH SQUARE-BRACKET DATAFUNCTIONS. ***
#    This is the fact the whole design rests on, and it is the one place where
#    error_log beats debug_log outright. Verbatim vanilla:
#      GAME\common\scripted_effects\00_setup_tests_effect.txt:10
#        error_log = "[THIS.Char.GetLogName] is married but not an adult!"
#      GAME\events\dlc\ep2\wedding_events\ep2_wedding_events.txt:1282
#        error_log = "Invalidating [activity.GetName] of [activity.GetOwner.GetLogName] because a spouse is dead"
#    CONTRAST debug_log: of 221 `debug_log =` lines measured across
#    GAME\common and GAME\events, ZERO contain a square bracket. debug_log's
#    only route to dynamic text is an unquoted LOC KEY
#    (`debug_log = debug_log.swing_scales.diarch_swung`, 24 such call sites),
#    which would have put every line of this telemetry in a .yml file owned by
#    another author. error_log needs no loc key at all.
#
# 3. WHICH FILE. Error severity, so it lands in
#      C:\Users\Pavel\...\Crusader Kings III\logs\error.log
#    and is mirrored into game.log, exactly as every other [E] line is - both
#    files in this install carry the same character_interaction.cpp:900 lines.
#    *** THE USER SENDS error.log. *** Vanilla confirms the destination in its
#    own words at 00_romance_effects.txt:399, discussing two error_log calls:
#    "this does lead to potential duplication in the error log".
#
# 4. *** IT DOES NOT NEED DEBUG MODE. *** This is why error_log was chosen over
#    debug_log, and the brief's instruction is explicit: prefer the mechanism
#    that works in normal mode even if it is less pretty. The evidence:
#      * NOT ONE of the 16 vanilla error_log call sites is wrapped in
#        `limit = { debug_only = yes }`. They sit on ordinary gameplay paths -
#        had_sex_with_effect, exact-tribute, a wedding invalidation - which
#        would be pointless if the call wrote nothing in a normal session.
#      * debug_log's call sites ARE so wrapped, repeatedly, e.g.
#        GAME\common\scripted_effects\10_dlc_tgp_house_bloc_scripted_effects.txt:904-908.
#      * Error severity is emitted in normal sessions, but is NOT unlimited.
#        The 2026-09-29 run stopped at exactly 100,000 error headers after a
#        GUI localization flood. TNTLOG ended in 1181; the save reached 1188.
#        Always check log coverage before interpreting missing events.
#    HONEST LIMIT OF THE PROOF: this is inference from vanilla's own usage plus
#    severity, not a runtime A/B of one session with the flag and one without,
#    which cannot be done from the file system. If the very first test run
#    produces no TNTLOG line at all AND the game rule was on, that inference is
#    the thing to doubt - relaunch in debug mode and compare. Nothing else in
#    the design changes if that turns out to be needed.
#
# 5. ONE LINE PER CALL. The engine prepends its own header, so a line looks like
#      [00:41:07][E][<source>.cpp:NNN]: file: common/scripted_effects/tnt_3b_log.txt line: NNN (tnt_log_try_effect): TNTLOG|v1|TRY|...
#    measured from debug_log's equivalent emitter, jomini_effect_impl.cpp:450.
#    *** THEREFORE `TNTLOG` IS NOT AT THE START OF THE LINE. *** Grep for it
#    anywhere in the line, never with a `^` anchor. The free `(effect_name)`
#    the engine adds is a bonus: it names the helper that emitted the line.
#    NO STRING IN THIS FILE MAY CONTAIN \n - that would break one-event-per-line,
#    which is the property the whole analysis depends on.
#
# 6. THE DATE. `[GetCurrentDate.GetYear]` is a global datafunction and needs no
#    scope - REAL, GAME\localization\english\coronation_events_l_english.yml:204
#    ("The Great Stampede of [GetCurrentDate.GetYear]"). Only the YEAR is put on
#    event lines, on purpose: it is pure ASCII digits, whereas
#    [GetCurrentDate.GetStringLong] (core_l_english.yml:44) renders through the
#    active language and would write Cyrillic month names into the data file on
#    this user's install. Ordering INSIDE a year comes from the engine's own
#    [HH:MM:SS] wall clock, which is monotonic across a single session, and a
#    half-year run is a single session. The full localised date is printed once,
#    on the BANNER line, where a human reads it and nothing parses it.
#
#=======================================================================
# WHAT IS PROVEN ABOUT EVERY DATAFUNCTION USED BELOW
#=======================================================================
#   [X.Char.GetLogName]                  00_setup_tests_effect.txt:10 (inside error_log)
#   [scope_name.GetLogName]              ep2_wedding_events.txt:1282 (inside error_log)
#   [named_scope.Char....]               battles_l_english.yml:83 ([ROOT.Char.GetUINameNoTooltip])
#   [X.GetID]                            core_l_english.yml:78, :80
#   [ROOT.Var('x').GetValue]             debug_l_english.yml:339 (test.4.desc, 30+ uses)
#   [ROOT.Char.MakeScope...]             wars_l_english.yml:291
#   [X.MakeScope.ScriptValue('v')|0]     buildings_l_english.yml:2341
#                                        (GetPlayer.MakeScope.ScriptValue(...)|0)
#   [GetCurrentDate.GetYear]             coronation_events_l_english.yml:204
#   [GetCurrentDate.GetStringLong]       core_l_english.yml:44
#
# *** TEMPORARY SCOPES ARE VISIBLE TO THESE DATAFUNCTIONS. *** That is load-
# bearing here, because tnt_38_ai_world.txt's actor and recipient are
# save_temporary_scope_as. Proof: vanilla loc dereferences names that are
# demonstrably temporary -
#   [sub_region_temp.GetName]                buildings_l_english.yml:2576
#   [province_temp.GetBaronyNameExplicitly]  domicile_window_l_english.yml:84
#   [loan_passer_temp.GetShortUINamePossessive] decisions_l_english.yml:135
# and the engine's own scope dump lists temporary scopes under "Saved event
# targets:" alongside permanent ones (house_member_temp, from
# 10_dlc_tgp_house_bloc_scripted_effects.txt:856 `save_temporary_scope_as`).
#
# NO `$PARAMETER$` IS USED INSIDE ANY LOG STRING IN THIS FILE. Substitution into
# a quoted string has ZERO vanilla call sites - measured, no
# `(debug_log|error_log) = "...$` anywhere in the install - so under R2 it is not
# relied on. That is why there is one helper per event kind with its own literal
# string rather than one parameterised helper. It costs lines here and buys
# certainty in the log.
#
#=======================================================================
# THE GATE. NOTHING HERE RUNS UNLESS THE GAME RULE IS ON.
#=======================================================================
# Every helper opens with `has_game_rule = tnt_ai_telemetry_on` or
# `..._verbose`, so at the shipped default (off) each one costs a single
# has_game_rule lookup and returns. The rule is declared in
# common\game_rules\tnt_81_ai_rules.txt (rule 3) and defaults to OFF.
#   has_game_rule inside a scripted effect's `limit`: this mod's own shipped
#   practice, tnt_37_ai_offer.txt:264 and five more in that file.
#
# NOTHING IN THIS FILE IS REACHED FROM A SCRIPT VALUE, A GUI BINDING, A
# `visible`, AN `is_shown` OR ANY PER-ROW PATH. Every caller is an AI pulse that
# runs at most twice per character per year, or a deal that is actually applied.
# That is the brief's hard rule and it is checkable: grep the mod for
# tnt_log_ and every CALL SITE is in one of SIX files - tnt_37 / tnt_38 /
# tnt_32 / tnt_34 / tnt_70 / events\tnt_ai_events.txt.
#   *** tnt_34 IS NEW IN ROUND 11, tnt_70 IN V33 (L21); THE THREE-FILE LINE IS DEAD. ***
#   *** AND SO IS THE FIVE-FILE LINE THAT REPLACED IT, 2026-08-24: IT OMITTED
#   *** events\tnt_ai_events.txt, WHICH IS NOT OBSCURE - IT CARRIES TEN LIVE
#   *** CALL SITES (:147 dispatch, :430 demand_abort, :852 abort, :1459 and
#   *** :1807 verdict_accept, :1499 verdict_counter, :1520 and :1859
#   *** verdict_decline, :1788 demandend_paid, :1852 demandend_refused), and
#   *** run C proves they fire: 108 DISPATCH, 108 OUTCOME, 8 REJECT records.
#   *** The enumeration IS the audit surface for the hard rule above, so an
#   *** auditor who greps only the five named script files and never opens
#   *** events\ would pass a call added to an option's rendered path unseen -
#   *** which is exactly the tooltip-mode case the paragraph below had to
#   *** special-case. RE-MEASURE THIS LINE, NEVER INCREMENT IT. ***
#   The fourth caller is tnt_wed_one_pair_effect (tnt_34_marriage.txt), which
#   calls L20 tnt_log_wedally_effect once per staged marriage pair. THAT IS
#   STILL NOT A PER-FRAME PATH and the hard rule is intact: that effect is the
#   body of an every_in_list inside tnt_exec_marriage_pair_effect, which is an
#   exec leg of tnt_apply_deal_effect - i.e. it runs only when a treaty is
#   actually signed, at most a handful of times per applied deal, on a click
#   path. The one thing that IS different from the other three files is that
#   this caller renders in TOOLTIP mode as well as at run time, so the call
#   site wraps it in hidden_effect; see L20's own header and house law 10d.
#
# VERBOSE exists only to separate "the pulse was evaluated and the dice said no"
# from "the pulse never ran". At `on`, per-evaluation lines are suppressed and
# only real decisions are written; see the volume table in the reader's guide.
########################################################################


########################################################################
# L0 - tnt_log_banner_effect         root = any character
#
# The proof-of-life line. It exists so that "no TNTLOG lines in the log" can
# never be confused with "the feature was off" or "the log is the wrong file".
#
# NO CALLER SINCE THE BANNER-SPAM FIX (V11, user item 2). It fired once per
# attempt from the top of tnt_ai_offer_try_effect and from inside
# tnt_ai_world_pulse_effect's chance gate, i.e. 1:1 with TRY and with WTRY, which
# are emitted on the very next line under the very same rule gate and already
# carry y=. That made it 24.3% of a measured 11,798-line run and 0% of its
# information: BANNER 2872 = TRY 1108 + WTRY 1764, exactly. Proof of life is now
# COUNT(TRY) + COUNT(WTRY) > 0, which is available under either pulse family and
# survives the log being truncated from the front just as well.
#
# THE BODY IS KEPT, NOT DELETED, so nothing dangles and the format version has a
# home if it is ever wanted again. If a human-readable date line IS wanted again,
# call this from ONE place that runs at most once per year - never from a pulse.
# The old trade-off recorded here (fire-once would need a new saved variable on a
# character, i.e. new savegame state for a diagnostic) was priced against firing
# once; it was never priced against not firing at all, which costs nothing
# because TRY and WTRY sit on the same two lines.
#
# It carries the FULL localised date because a human reads this line.
########################################################################
tnt_log_banner_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}
		error_log = "TNTLOG|v1|BANNER|y=[GetCurrentDate.GetYear]|date=[GetCurrentDate.GetStringLong]|note=parley AI telemetry active"
	}
}


########################################################################
# SECTION A - THE AI-TO-PLAYER OFFER PATH (tnt_37_ai_offer.txt)
#
# Field vocabulary, identical in every kind that carries it:
#   y      the in-game year
#   pro    the AI proposer, GetLogName (name + internal id + historical id)
#   proid  the proposer's numeric character id, for joining lines
#   tgt    the intended recipient - the human player
#   tgtid  the recipient's numeric character id
#   via    how the recipient was found: neigh (the neighbour iterator) or
#          liege (the one-link fallback)
#   why    the single reason this attempt stopped. One token, one cause.
#   rate   the tnt_ai_offer_rate setting in force
########################################################################


########################################################################
# L1 - tnt_log_try_effect            root = THE AI PROPOSER
#
# ATTEMPT START. Emitted after `save_scope_as = tnt_ai_proposer`, so the scope
# is live. One line per attempt that got past the pulse's own trigger and its
# 11 per cent dice - i.e. the denominator for every rejection count below.
#
# THE `rate` FIELD IS WHY THIS HELPER IS FIVE BRANCHES INSTEAD OF ONE LINE.
# There is no proven datafunction that reads a game rule, and no parameter
# substitution into a log string (see the file header), so each setting names
# its own complete literal. The payoff is that EVERY attempt line states the
# rate in force, which means a reader never has to cross-reference a banner and
# a truncated log is still fully interpretable. The if/else_if ladder is the
# same shape tnt_37_ai_offer.txt already uses to pick its cooldown durations.
########################################################################
tnt_log_try_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}

		if = {
			limit = { has_game_rule = tnt_ai_offer_rate_test }
			error_log = "TNTLOG|v1|TRY|y=[GetCurrentDate.GetYear]|rate=test|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]"
		}
		else_if = {
			limit = { has_game_rule = tnt_ai_offer_rate_frequent }
			error_log = "TNTLOG|v1|TRY|y=[GetCurrentDate.GetYear]|rate=frequent|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]"
		}
		else_if = {
			limit = { has_game_rule = tnt_ai_offer_rate_rare }
			error_log = "TNTLOG|v1|TRY|y=[GetCurrentDate.GetYear]|rate=rare|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]"
		}
		else_if = {
			limit = { has_game_rule = tnt_ai_offer_rate_normal }
			error_log = "TNTLOG|v1|TRY|y=[GetCurrentDate.GetYear]|rate=normal|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]"
		}
		else = {
			# Unreachable in practice: the `off` setting is handled by L2, which
			# runs in the else branch of the rule test in tnt_ai_offer_try_effect
			# and therefore never reaches this helper. Present so the ladder is
			# total and a future sixth setting cannot silently drop the line.
			error_log = "TNTLOG|v1|TRY|y=[GetCurrentDate.GetYear]|rate=other|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]"
		}
	}
}


########################################################################
# L2 - tnt_log_rule_off_effect       root = THE AI PROPOSER
#
# why=rule_off. THE MOST IMPORTANT NEGATIVE LINE IN THE FILE, because "the AI
# made no offers" and "I left the rule at off" are otherwise the same log.
# Emitted from a new `else` on the rule test that already opens
# tnt_ai_offer_try_effect - the original `if` and its body are untouched.
#
# It does NOT use scope:tnt_ai_proposer: that save_scope_as sits INSIDE the
# if-branch this else is the sibling of, so the scope does not exist here.
# root is the AI, hence THIS.
########################################################################
tnt_log_rule_off_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}
		error_log = "TNTLOG|v1|NOTRY|y=[GetCurrentDate.GetYear]|why=rule_off|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]"
	}
}


########################################################################

# *** THIS IS EXPECTED TO BE THE COMMONEST LINE IN THE WHOLE LOG, AND THAT IS
# NOT A BUG. *** The candidate limit requires `is_ai = no`, so in single player
# the ONLY legal recipient in the world is the one human. Every AI that is not
# a neighbour of the player must produce this line. The reader's guide says so
# again where the counts are interpreted; without this note the first analyst
# will report a phantom fault.
########################################################################
tnt_log_nocand_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}
		error_log = "TNTLOG|v1|NOTRY|y=[GetCurrentDate.GetYear]|why=no_candidate|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]"
	}

########################################################################
# L5 - THE GATE-FAILURE LADDER      root = THE AI PROPOSER
#
# A candidate was found and then rejected by the final compound gate. The
# compound `if` in tnt_ai_offer_try_effect tests seven things at once and a
# single "gate failed" line would collapse seven different causes into one
# number - precisely the failure the brief forbids. So the ORIGINAL `if` IS LEFT
# EXACTLY AS IT WAS and a new `else` runs this diagnostic ladder, which re-tests
# the rows one at a time, cheapest first, and names the first one that fails.
#
# WHY A LADDER AND NOT SEVEN INDEPENDENT TESTS: `if / else_if` stops at the
# first failure, so exactly one line is written per rejected candidate. That
# keeps the counts addable - the reasons partition the rejections instead of
# overlapping.
#
# THE COST IS PAID ONLY ON FAILURE AND ONLY WHEN LOGGING IS ON. The ladder is
# inside the telemetry gate, so at the shipped default it is one has_game_rule
# lookup. Even when on it is a handful of flat field reads plus, in the worst
# case, one tnt_partner_valid_trigger - the same trigger the gate itself just
# evaluated, on a path that runs at most twice per AI per year.
#
# ROW ORDER MIRRORS THE GATE'S OWN ORDER so that "the first row that fails" means
# the same thing in both places. partner_gate is tested LAST despite being first
# in the gate, because it is the only expensive row and the cheap rows explain
# most rejections; a reader who needs the gate's own precedence has the raw rows.
########################################################################
tnt_log_gatefail_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}

		if = {
			limit = { scope:tnt_ai_target = { is_ai = yes } }
			set_variable = { name = tnt_log_b  value = scope:tnt_ai_target }
			error_log = "TNTLOG|v1|REJECT|y=[GetCurrentDate.GetYear]|why=target_is_ai|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]|tgt=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetLogName]|tgtid=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetID]"
			remove_variable = tnt_log_b
		}
		else_if = {
			limit = { scope:tnt_ai_target = { is_landed = no } }
			set_variable = { name = tnt_log_b  value = scope:tnt_ai_target }
			error_log = "TNTLOG|v1|REJECT|y=[GetCurrentDate.GetYear]|why=target_unlanded|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]|tgt=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetLogName]|tgtid=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetID]"
			remove_variable = tnt_log_b
		}
		else_if = {
			limit = { scope:tnt_ai_target = { exists = var:tnt_open } }
			set_variable = { name = tnt_log_b  value = scope:tnt_ai_target }
			error_log = "TNTLOG|v1|REJECT|y=[GetCurrentDate.GetYear]|why=target_window_open|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]|tgt=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetLogName]|tgtid=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetID]"
			remove_variable = tnt_log_b
		}
		else_if = {
			limit = { scope:tnt_ai_target = { exists = var:tnt_partner } }
			set_variable = { name = tnt_log_b  value = scope:tnt_ai_target }
			error_log = "TNTLOG|v1|REJECT|y=[GetCurrentDate.GetYear]|why=target_busy_negotiating|pro=[THIS.Char.GetLogName]|proid=[THIS.Char.GetID]|tgt=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetLogName]|tgtid=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetID]"
			remove_variable = tnt_log_b
		}
		else_if = {
			limit = {
				NOT = { has_game_rule = tnt_ai_offer_rate_test }
				scope:tnt_ai_target = { exists = var:tnt_ai_offer_cooldown }
			}
			set_variable = { name = tnt_log_b  value = scope:tnt_ai_target }

# L9 - tnt_log_settle_effect         root = THE PLAYER
#
# THE NUMBERS. Emitted at the end of tnt_ai_offer_settle_effect, after
# tnt_ai_pricebalance_effect has done its one corrective pass, so these are the
# figures the offer will actually be judged on.
#
# WHY THESE FIVE AND NOT THE WHOLE 55-VALUE CHAIN: they are exactly the rows
# tnt_ai_accept_value itself is built from (tnt_50_values.txt:3553-3618), so they
# reconstruct the verdict arithmetically -
#     accept = gain - loss + rel - thresh        (then `round = yes`)
# and a reader can therefore see WHICH row carried or sank the deal without a
# second query.
#   accept  tnt_ai_accept_value      the headline. > 0 means this AI would sign.
#   gain    tnt_gain_total_value     everything the partner receives
#   loss    tnt_loss_total_value     everything the partner hands over
#   rel     tnt_relation_mod_value   the standing between the two rulers, the
#                                    rounded sum of the eight tnt_relmod_* parts
#                                    the acceptance panel prints separately
#   thresh  tnt_threshold_value      what he wants on top of a merely fair trade
# All five verified present: tnt_50_values.txt:3553, :2304, :2622, :3272, :3429.
#
# margin=1 ceiling=1 are the literals tnt_ai_offer_settle_effect passes to
# tnt_ai_pricebalance_effect. They are written here as constants on purpose: if
# somebody re-tunes them, the log of the old run still records what was in
# force. (The line printed 8|20 for one whole playtest after the settle moved to
# 1|1 - a stale literal is exactly the failure this sentence was warning about,
# and the 2026-08 run had to be read around it. Re-tune the settle, re-tune this
# string, same commit.) NOTE the EFFECTIVE ceiling on a capped-gift letter is
# margin + the excess over tnt_ai_generosity_cap_value - the ceiling-raise block
# in tnt_39_autobalance.txt - which is why the line also prints gifthead=
# (tnt_ai_gift_headroom_value, tnt_53_currency_values.txt section 4b): 0 on an
# ordinary letter, and on a gift letter the headroom the letter ships with.
#
# EVALUATING FIVE NAMED VALUES COSTS FIVE FULL VALUE CHAINS. That is the single
# most expensive thing this telemetry does, and it is bounded to once per
# composed offer - a path already described in its own header as "about a dozen
# evaluations, ONCE, for an event that fires at most once per AI per one to six
# years". It is behind the game rule, so it is not paid in ordinary play.
########################################################################
tnt_log_settle_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}
		set_variable = { name = tnt_log_n1  value = tnt_ai_accept_value }
		set_variable = { name = tnt_log_n2  value = tnt_gain_total_value }
		set_variable = { name = tnt_log_n3  value = tnt_loss_total_value }
		set_variable = { name = tnt_log_n4  value = tnt_relation_mod_value }
		set_variable = { name = tnt_log_n5  value = tnt_threshold_value }
		set_variable = { name = tnt_log_n6  value = tnt_ai_gift_headroom_value }
		error_log = "TNTLOG|v1|SETTLE|y=[GetCurrentDate.GetYear]|tgtid=[THIS.Char.GetID]|accept=[THIS.Char.MakeScope.Var('tnt_log_n1').GetValue]|gain=[THIS.Char.MakeScope.Var('tnt_log_n2').GetValue]|loss=[THIS.Char.MakeScope.Var('tnt_log_n3').GetValue]|rel=[THIS.Char.MakeScope.Var('tnt_log_n4').GetValue]|thresh=[THIS.Char.MakeScope.Var('tnt_log_n5').GetValue]|margin=1|ceiling=1|gifthead=[THIS.Char.MakeScope.Var('tnt_log_n6').GetValue]"
		remove_variable = tnt_log_n1
		remove_variable = tnt_log_n2
		remove_variable = tnt_log_n3

		remove_variable = tnt_log_n5

	}

#                thing those two strings can mean now, and it is worth one word.
#   pts=         tnt_threat_points_value for the (proposer, player) pair. Under
#                the ruling this ONE number is the verdict (>= 100), the distance
#                from the bar, and the ask (0.15 x pts x the gold rate, capped at

#                run's compositions it is THE DISTRIBUTION OF THE AI'S LEVERAGE

#

# verbose this helper costs one has_game_rule lookup and evaluates T53 not at

		root = { save_temporary_scope_as = tnt_thr_you }

### V4 EXPANSION 1 - THE ULTIMATUM, arch=ultimatum. Three kinds, because an
### ultimatum has one more way to end than the other archetypes: it can be CHOSEN
### and then refused by the recipient's own balance, and a half-year run needs that
### distinguishable from "never tried". WARCH says it was picked, WDONE says gold
### moved, WSKIP says the demand was refused.
###
### *** REWORKED 2026-08-25 (lane 3), AND THE OLD SHAPE COST A WHOLE-LOG HARVEST.
### TWO FAULTS, BOTH FIXED HERE:
###   (1) ONE LABEL OVER TWO CAUSES. why=fear_too_small_or_broke was the only
###       reason WSKIP could give, and the two causes it merged mean OPPOSITE
###       things - "he was not frightened enough" is a pricing observation,
###       "he was willing and had no money" is an economy one. The 2026-08-25
###       run split 48 broke against 1 unafraid, and no amount of re-reading the
###       label could have told anyone that. It is now two labels, re-tested one
###       row at a time in the same order E17's own gate tests them - the shape
###       tnt_log_gatefail_effect above uses, and for the same reason.
###   (2) THE ULTIMATUM WAS THE ONLY BROKE BUCKET IN THE SANDBOX THAT PRINTED NO
###       PURSE AT ALL. Every other one carries gold_have, so diagnosing this
###       archetype needed 310 readings harvested out of OTHER archetypes'
###       buckets instead of one grep of its own. It now prints the payer's
###       capacity as cap.
### WHY cap AND NOT gold_have. gold_have is read off THIS (the actor) at every
### other site, and here the payer is scope:recipient, so the field would have
### printed the wrong man's purse. cap is tnt_ai_demand_purse_cap_value = 0.8 x
### the PAYER's gold - the number that actually decides - it needs no new value
### and no unproven datafunction, and the purse itself is cap / 0.8 exactly.
###
### THE FIVE NUMBERS, and they are deliberately the DEMAND probe's own vocabulary
### (L16 above) because it is the same mechanic seen from the other path:
###   pts   tnt_ai_threat_points_value      the pressure
###   gold  tnt_ai_ultimatum_gold_value     the RAW ask, 15% of pts in coin
###   cap   tnt_ai_demand_purse_cap_value   80% of the payer's purse
###   ask   tnt_ai_demand_gold_value        what is ACTUALLY demanded = min(gold,cap)
###   bal   tnt_ai_deal_ultimatum_value     what the recipient made of it
### gold != ask MEANS THE CLAMP BIT - the same one-line reading rule L16 states.
### A line reading pts=63030 ask=17 is CORRECT and is not a bug: the points value
### is uncapped by the user's order and the purse contains the coin.
tnt_log_warch_ultimatum_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}
		set_variable = { name = tnt_log_b  value = scope:recipient }
		set_variable = { name = tnt_log_n1  value = tnt_ai_threat_points_value }
		error_log = "TNTLOG|v1|WARCH|y=[GetCurrentDate.GetYear]|arch=ultimatum|a=[THIS.Char.GetLogName]|aid=[THIS.Char.GetID]|b=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetLogName]|bid=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetID]|pts=[THIS.Char.MakeScope.Var('tnt_log_n1').GetValue]"
		remove_variable = tnt_log_b
		remove_variable = tnt_log_n1
	}
}

# NO TIER WAS BOTH AFFORDABLE AND BALANCED. The two causes are separated,
# because they mean opposite things: `broke` is the AI having less gold than the
# cheap tier costs, `unbalanced` is the recipient refusing at a price the actor
# could pay. One is an economy observation, the other is a pricing observation.
tnt_log_wabort_broke_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}
		# gold_have uses GetGold, NOT GetShortTermGold - the latter has zero call
		# sites in this install and does not exist as a datafunction (R2). GetGold
		# is REAL: GAME\localization\english\ingame_main_l_english.yml:222
		# ([GetPlayer.GetGold|0V]) and core_l_english.yml:296. The .Char promote on
		# a named scope is battles_l_english.yml:83.
		#   *** V15: THE NOTE THAT STOOD HERE WAS FALSE, AND ITS FALSENESS COST TWO
		#   *** ROUNDS OF MISREADING THIS FIELD. *** It said the script tested
		#   `short_term_gold`, that GetGold and short_term_gold "agree on an AI with
		#   no active loans", and that a gold_have well above gold_need was therefore
		#   that difference "and not a broken test". The escape clause fired 16 times
		#   in the 2026-08-17 run, and the stated mechanism was wrong: short_term_gold
		#   is a BUDGET CATEGORY sitting behind the war-chest skim
		#   (GAME\common\defines\ai\00_ai.txt:100-105 BUDGET_CATEGORY, :139-147
		#   MIN_WAR_CHEST, :154, :161), nothing to do with loans. A count holding 51
		#   gold really did fail a 25-gold gate. So every `broke` line here reported a
		#   number that CONTRADICTED its own verdict, and the mod read the buckets as
		#   an economy observation instead of a predicate bug for two rounds.
		#   THE CONTRADICTION IS GONE RATHER THAN DOCUMENTED: the gates on this path
		#   now test plain `gold` (see E1's header in tnt_38_ai_world.txt), which is
		#   exactly what GetGold prints. gold_have and gold_need are directly
		#   comparable again, and a `broke` line showing have >= need is now a REAL
		#   defect to chase rather than an expected artefact. No st_gold field was
		#   added, because there is no longer anything for it to explain.
		set_variable = { name = tnt_log_b  value = scope:recipient }
		set_variable = { name = tnt_log_n1  value = tnt_ai_gold_low_value }
		error_log = "TNTLOG|v1|WSTOP|y=[GetCurrentDate.GetYear]|why=actor_broke|aid=[THIS.Char.GetID]|bid=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetID]|gold_have=[THIS.Char.GetGold|0]|gold_need=[THIS.Char.MakeScope.Var('tnt_log_n1').GetValue]"
		remove_variable = tnt_log_b
		remove_variable = tnt_log_n1
	}
}

# L18 - tnt_log_apply_effect         root = THE PLAYER
#
# The one line that says a package stopped being a proposal. It is emitted from
# the top of tnt_apply_deal_effect's success branch, so it fires for BOTH paths
# the master effect serves - the player's own manual Propose and the AI's letter
# once accepted - and its own header confirms the rooting is identical on both
# ("root is ALWAYS the player and scope:tnt_deal_partner is ALWAYS the other
# ruler, on both the manual path and the planned AI path").
#
# *** THIS IS ALSO THE PLAYER-SIDE INSTRUMENTATION THE BRIEF ASKS FOR, item 6.
# *** src distinguishes the two paths by a fact already on the character:
# tnt_ai_offer_arch exists only on the AI path (set by the composer, days = 200,
# removed by every exit). So:
#     src=ai_offer   the AI wrote this package and the player accepted it
#     src=player     the player built it in the window and pressed Propose
# accept= is tnt_ai_accept_value on the SAME package, which is what makes the
# comparison the brief wants possible: the AI's own pricing of a deal the player
# composed, against its pricing of the deals it composes itself. Group SETTLE by
# archetype, group APPLY by src, compare the accept columns.
#
# WHY THE VALUE IS RE-EVALUATED HERE rather than carried from SETTLE: on the
# manual path there is no SETTLE line at all, so there would be nothing to carry.
# One value chain, once, at the moment a deal is signed.
########################################################################
tnt_log_apply_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}

		# V18, USER ITEM 3 - osided= IS NEW AND IT IS THE STRESS LAYER'S ONLY
		# INSTRUMENT. The user has asked twice how the deal stress works and could
		# not tell from play; nothing in the mod logs it, so it could not be told
		# from a log either. osided is tnt_stress_onesided_value on the package
		# about to be signed - gain minus twice loss (tnt_5a_stress_values.txt) -
		# which is the exact quantity leg 2 of tnt_stress_deal_effect tests against
		# the 200 rung. With it, the whole layer becomes answerable from one query:
		# leg 2 fired iff the deal was manual and osided >= 200. Leg 1 (the threat)
		# is answerable from the new item=threat TERM3 row added in L19 below.
		#
		# *** V30 - osided= NO LONGER NAMES A QUANTITY ANY LEG TESTS, AND THE TWO
		# *** NEW FIELDS BESIDE IT ARE WHAT THE STRESS LAYER NOW READS. ***
		# READ THE PARAGRAPH ABOVE AS HISTORY. tnt_stress_deal_effect was rewritten
		# from two legs over add_stress to FIVE ARMS over stress_impact, and the
		# measure changed from NET to GROSS in the same edit:
		#     gave= is tnt_stress_gave_value = tnt_gain_total_value, i.e. everything
		#           the PARTNER receives, i.e. everything the player handed over.
		#           Arms B: gave >= 200 (grave) and gave >= 75 (ordinary).
		#     took= is tnt_stress_took_value = tnt_loss_total_value, i.e. everything
		#           the partner hands over, i.e. everything the player took in.
		#           Arms C: took >= 200 (grave) and took >= 75 (ordinary).
		#     osided= is KEPT, is retired from every gate, and this emitter pair is
		#           now its ONLY reader in the whole mod. It stays because it is the
		#           one continuous series the layer has across runs and because
		#           deleting a registered value breaks a live caller.
		# THE FIELDS WERE ADDED IN THE SAME EDIT AS THE CODE, ON PURPOSE. A log that
		# names a quantity no leg tests is the exact shape of the V7b/V17 guard
		# defect, where the code and the telemetry silently disagreed for three
		# rounds and nothing in the game hinted at it. If a later round moves the
		# measure again, it moves these fields in the same commit or it repeats that
		# defect knowingly.
		#
		# WHAT THE THREE FIELDS ANSWER TOGETHER, and this is the whole query:
		#   arm A fired iff letter=0 AND the deal carried a threat or a spent hook
		#         (the item=threat / item=usehook TERM3 rows in L19 below) AND the
		#         signer held one of seven traits, which no log field records.
		#   arm B fired iff letter=0, arm A did not, and gave >= 75.
		#   arm C fired iff letter=0, neither A nor B did, and took >= 75.
		# THE TRAIT TEST IS DELIBERATELY NOT LOGGED. It would need seven has_trait
		# bridges per record for a fact the player can read off his own character
		# sheet, and the rung calibration - the thing the next run must decide - does
		# not depend on it. gave= and took= are what re-derive the two rungs against
		# real manual-deal data; the run-B set was only n=2.
		# THE POSITION IS ALREADY RIGHT: this effect runs at slot 3 of
		# tnt_apply_deal_effect, above every exec leg, so the term variables the
		# value reads are still intact - the same argument the accept= field makes.
		# The tnt_log_n2 bridge is mandatory, not stylistic: a script value cannot
		# be interpolated into error_log directly, which is why tnt_log_n1 exists.
		# tnt_log_n4 and tnt_log_n5 are the same bridge for gave= and took=. They
		# are set and removed inside each branch, before tnt_log_terms_applied_effect
		# is called at the foot of this effect, so the names are free to be reused
		# by the term sweep exactly as n1 and n2 already are.
		# NOTE src= STILL BRANCHES ON var:tnt_ai_offer_arch, which is NOT the stress
		# guard: the guard is now a saved scope value written by the letter's accept
		# option (tnt_3c_stress.txt). The arch variable is days = 200 and can expire
		# under an open letter, so src=player is not proof the layer was eligible.
		# WAS THE STRESS LAYER ELIGIBLE ON THIS DEAL? (V18, user item 3.)
		# The guard tnt_3c_stress.txt reads is `exists = scope:tnt_deal_from_letter`,
		# a saved scope value the letter's accept option writes immediately before
		# tnt_apply_deal_effect. It is NOT the same fact as src= above, which branches
		# on var:tnt_ai_offer_arch - a days = 200 variable that can expire while a
		# letter sits unanswered. So src=player did not prove the layer had charged,
		# and "how does stress work" stayed unanswerable from the log for three rounds.
		# One field closes it: letter=1 means the deal came through a letter and the
		# stress legs were SUPPRESSED; letter=0 means a manual treaty and they RAN.
		# Bridged through a variable because a saved scope value cannot be interpolated
		# into error_log directly - the same reason tnt_log_n1 and tnt_log_n2 exist.
		if = {
			limit = { exists = scope:tnt_deal_from_letter }
			set_variable = { name = tnt_log_n3  value = 1 }
		}
		else = {
			set_variable = { name = tnt_log_n3  value = 0 }
		}
		if = {
			limit = { exists = var:tnt_ai_offer_arch }
			set_variable = { name = tnt_log_n1  value = tnt_ai_accept_value }
			set_variable = { name = tnt_log_n2  value = tnt_stress_onesided_value }
			set_variable = { name = tnt_log_n4  value = tnt_stress_gave_value }
			set_variable = { name = tnt_log_n5  value = tnt_stress_took_value }
			error_log = "TNTLOG|v1|APPLY|y=[GetCurrentDate.GetYear]|src=ai_offer|arch=[THIS.Char.MakeScope.Var('tnt_ai_offer_arch').GetValue]|me=[THIS.Char.GetLogName]|meid=[THIS.Char.GetID]|other=[THIS.Char.MakeScope.Var('tnt_partner').Char.GetLogName]|otherid=[THIS.Char.MakeScope.Var('tnt_partner').Char.GetID]|accept=[THIS.Char.MakeScope.Var('tnt_log_n1').GetValue]|osided=[THIS.Char.MakeScope.Var('tnt_log_n2').GetValue]|gave=[THIS.Char.MakeScope.Var('tnt_log_n4').GetValue]|took=[THIS.Char.MakeScope.Var('tnt_log_n5').GetValue]|letter=[THIS.Char.MakeScope.Var('tnt_log_n3').GetValue]"
			remove_variable = tnt_log_n1
			remove_variable = tnt_log_n2
			remove_variable = tnt_log_n4
			remove_variable = tnt_log_n5
		}
		else = {
			set_variable = { name = tnt_log_n1  value = tnt_ai_accept_value }
			set_variable = { name = tnt_log_n2  value = tnt_stress_onesided_value }
			set_variable = { name = tnt_log_n4  value = tnt_stress_gave_value }
			set_variable = { name = tnt_log_n5  value = tnt_stress_took_value }
			error_log = "TNTLOG|v1|APPLY|y=[GetCurrentDate.GetYear]|src=player|arch=none|me=[THIS.Char.GetLogName]|meid=[THIS.Char.GetID]|other=[THIS.Char.MakeScope.Var('tnt_partner').Char.GetLogName]|otherid=[THIS.Char.MakeScope.Var('tnt_partner').Char.GetID]|accept=[THIS.Char.MakeScope.Var('tnt_log_n1').GetValue]|osided=[THIS.Char.MakeScope.Var('tnt_log_n2').GetValue]|gave=[THIS.Char.MakeScope.Var('tnt_log_n4').GetValue]|took=[THIS.Char.MakeScope.Var('tnt_log_n5').GetValue]|letter=[THIS.Char.MakeScope.Var('tnt_log_n3').GetValue]"
			remove_variable = tnt_log_n1
			remove_variable = tnt_log_n2
			remove_variable = tnt_log_n4
			remove_variable = tnt_log_n5
		}
		remove_variable = tnt_log_n3

		tnt_log_terms_applied_effect = yes
	}
}

# *** ROOT = A LIST MEMBER, NOT THE PLAYER. ***
# Every other helper in this file says "root = THE PLAYER" and this one does

# full three-hypothesis argument is in tnt_exec_marriage_pair_effect's header
# (tnt_34_marriage.txt). Stage two qualifying couples in one treaty and read

#

# actually survived in play. That claim currently rests on vanilla's script
# rather than on a measurement of ours - is_alliance_valid accepts
# `betrothed = scope:second` (GAME\common\scripted_rules\00_rules.txt:354) and
# on_alliance_broken breaks the betrothal of each reason pair
# (GAME\common\on_action\alliance_on_actions.txt:331-338) - so an adult=0 row

		limit = {

			}
			exists = scope:tnt_deal_partner
			exists = scope:tnt_wed_host

# nine and tnt_log_b / tnt_log_c1 are the only ones the uninstall decision
# sweeps (common\decisions\tnt_86_uninstall.txt). Nine bridges, nine fields.
# A TENTH FIELD COSTS A NAME IN THAT FILE FIRST.
#
# THE FOUR ROW COUNTS ARE INDEPENDENT, NOT NESTED, ON PURPOSE. A nested
# ladder would only ever report "the first row failed", and not knowing
# WHICH row failed is precisely what the last three rounds cost. pass= is
# the single nested figure and it is the alert's own conjunction.
#
# ---------------------------------------------------------------------
# LEANC - THE PER-CANDIDATE ROW, VERBOSE ONLY
#   TNTLOG|v1|LEANC|y=|pool=vassal|bid=|tp=
# One line per candidate per pool per year, so the aggregate above can be
# taken apart when it says something surprising: WHICH neighbour is the
# tpbest, whether the vassal pool and the neighbour pool live in different
# number ranges, whether the widened across-water half contributes anything
# at all. Volume is ~24-31 candidates x 6 years, order 200 lines against run
# D's 26,886 - and ZERO at the shipped default, because the whole helper
# returns on the has_game_rule row below.
#
# pool= IS THREE LITERAL STRINGS AND NOT A PARAMETER, per this file's
# no-substitution rule - the same shape ARTGATE and DEMANDGATE use.
#
# *** THE WHOLE ROW IS EMITTED INSIDE root = { }, AND THAT IS NOT COSMETIC. ***
# error_log resolves only THIS (every other scope comes back as a raw token),
# and inside an iterator body THIS is the CANDIDATE - so the obvious way to
# write this line is to put the bridge on the candidate and read it back off
# THIS. DO NOT. That mutates a variable on a walked member, which is exactly
# the defect tnt_family_gate.ps1 check 9 exists for: a remove_variable against
# a scope whose variable store the engine has already dropped is an ENGINE
# ERROR, not a no-op, and one such shape put 576 lines into a 20-minute run.
# Re-scoping to root instead costs one wrapper, keeps every write on a store
# the probe itself created a few lines earlier, and lets bid= come off the
# tnt_log_b object bridge the rest of this file already uses for a character.
#
# *** IT CALLS THE THREE TRIGGERS AND COPIES NOTHING, AND SINCE THE RULING
# *** IT READS THE ONE VALUE THEY READ. *** The threat rule has TWO authorised
# second copies, not one: tnt_threat_p_toggle.is_valid's inline rows
# (common\scripted_guis\tnt_20_scripted_guis.txt:540, rows :637 and :641) and
# T53 tnt_can_demand_trigger's rows 1 and 3 (tnt_41_gates.txt:2447, :2449).
# A FOURTH IS FORBIDDEN: a probe that restated it could disagree with the code
# it measures (L20 says the same of T54/yield=). tpbar=/tpbest= obey that rule
# from the value side: they call tnt_threat_points_value, the SAME value the
# gate, the window price and the AI's ask all read, and restate no part of it.
# The literal 5 is the gate's own bar and appears here for the same reason
# the gate has it - it is the ONE number the ruling put in the code.
#
# A = root AND B = scope:tnt_lean_b - NEVER `this`, NEVER `prev`. These
# triggers are TEXT MACROS and a relative handle re-binds inside the
# substituted body. THE RULE LIVES ONCE, at tnt_41_gates.txt:2385-2386; obey it
# and do not re-derive it. The story that stood here - and its twin in the
# alert - was invented and disagreed with itself; both are deleted. The saves
# are tnt_thr_me / tnt_thr_you (tnt_41_gates.txt:2396-2397), not tnt_me/tnt_p.
#
# *** THE PAIR IS SAVED IN THE BODY, BEFORE ANYTHING READS THE VALUE, AND
# *** UNGUARDED. *** tnt_threat_points_value resolves "me" and "him" through
# scope:tnt_thr_me / scope:tnt_thr_you, and its prologue is GUARDED (it fills
# them in when they are absent) - so on the second candidate of a walk a
# guarded prologue would keep the FIRST candidate's pair and price all 24 men
# identically. The two unguarded saves at the top of each iterator body are
# what make the walk honest; they are the same doctrine, in the same order,
# that tnt_can_threat_trigger itself ships (tnt_41_gates.txt, the saves sit
# first in the trigger_if body), written out at tnt_42_people_gates.txt
# :1002-1010 and shipped there since V26 with zero errors in a 444k-line log.
#
# WHAT IS DELIBERATELY NOT RESTATED. The alert's root gate is
# `is_landed = yes`, and NOTHING ELSE since the tnt_open kill switch was
# tombstoned there on 2026-08-24. It is not copied here: a landless
# player's every_vassal is empty, so the counts read 0 by themselves. The
# probe measures CANDIDACY; that row of the alert is about not nagging.
#
# COST. Three bounded iterators per PLAYER per YEAR - every_vassal,
# every_neighboring_and_across_water_top_liege_realm_owner and
# every_liege_or_above - and only when the telemetry rule is on; at the
# shipped default this helper is a single has_game_rule lookup. The 2026-08-24
# rewrite ADDS one script-value evaluation per candidate
# (tnt_threat_points_value, ~6 field reads and one divide) on top of the
# trigger calls that were already there. Vanilla spends far more on this
# identical question: GAME\common\important_actions\01_fp1_actions.txt:54
# walks every_ruler paying a full
# is_character_interaction_potentially_accepted per ruler. HOUSE LAW 6 IS NOT
# ENGAGED - no .gui visible, no row size, none of the 22 [TntValid(..)] /
# 19 [TntTip(..)] bindings, and this is a yearly effect over savegame state.
#
# THE FORMS, ALL PROVEN IN VANILLA:
#   bare field as a set_variable value    GAME\common\council_tasks\
#     00_steward_tasks.txt:491-494 (`value = development_level`)
#   root = { change_variable } counter inside an iterator
#     GAME\common\on_action\title_on_actions.txt:722-730
#   save_temporary_scope_as first in an every_vassal body
#     GAME\common\character_interactions\00_war.txt:414-415
#   every_liege_or_above with a per-candidate limit
#     GAME\common\important_actions\07_ep3_actions.txt:67-76
#   every_neighboring_and_across_water_top_liege_realm_owner
#     GAME\common\important_actions\00_war_actions.txt:13 (20 sites under
#     GAME\common)
#   *** A RUNNING MAXIMUM WITH NO COMPARISON - AND THE FORM WAS WRONG UNTIL
#   *** 2026-08-25: THE CLAMP LIVES INSIDE A NESTED `value = { }`, NEVER AT
#   *** THE TOP LEVEL OF change_variable. *** Self-referencing set_variable
#     over a nested block: GAME\common\scripted_effects\10_dlc_tgp_scripted_
#     effects.txt:1387-1393, `value = { value = var:<same name>  add = $VALUE$ }`
#     - and the same shape CARRYING THE CLAMP at 07_dlc_ep3_scripted_effects
#     .txt:10656-10664, `value = { value = ..var:X  add = 1  max = 5 }`. A
#     named script value in a min/max slot is proven 107 times in vanilla's
#     own script_values, e.g. 00_contract_script_values.txt:190. R7 has
#     nothing to bind because no comparison exists: the obvious
#     `if = { limit = { tnt_threat_points_value > var:tnt_log_n9 } }` is
#     illegal, and `order_by = tnt_threat_points_value` is WORSE THAN ILLEGAL
#     - the value re-anchors through saved scopes and an order_by does not
#     set them per candidate, so it would sort every man by the first's.
#
# BRIDGES n1..n9 for the aggregate line and tnt_log_b / tnt_log_c1 for LEANC,
# ALL OF THEM ON ROOT and all written and removed in the same call per this
# file's standing rule. All eleven names are already swept by the uninstall
# decision (common\decisions\tnt_86_uninstall.txt), so this helper adds no new
# savegame surface at all - and that is the constraint that fixes the field
# count at nine. See the ladder above before adding a tenth.
########################################################################
tnt_log_lean_probe_effect = {
	if = {
		limit = {
			OR = {
				has_game_rule = tnt_ai_telemetry_on
				has_game_rule = tnt_ai_telemetry_verbose
			}
		}

		# n1 vassals  n2 nbrs  n3 lieges   - the three pool sizes
		# n4 passT    n5 passDoor  n6 passT1  n7 pass  - the four predicates
		# n8 tpbar    n9 tpbest              - the bar, and the best man on it
		set_variable = { name = tnt_log_n1  value = 0 }
		set_variable = { name = tnt_log_n2  value = 0 }
		set_variable = { name = tnt_log_n3  value = 0 }
		set_variable = { name = tnt_log_n4  value = 0 }
		set_variable = { name = tnt_log_n5  value = 0 }
		set_variable = { name = tnt_log_n6  value = 0 }
		set_variable = { name = tnt_log_n7  value = 0 }
		set_variable = { name = tnt_log_n8  value = 0 }
		# tpbest STARTS AT ZERO AND CAN NEVER GO BELOW IT: every factor of
		# tnt_threat_points_value carries its own floor at 0 and so does the
		# product, so the max L21b takes over an accumulator seeded at 0 is a
		# true running maximum across the three pools. *** EVERY tpbest EVER
		# LOGGED BEFORE 2026-08-25 IS VOID - THE EMITTER PRINTED THAT 0, NOT
		# THE WORLD. Never cite an old tpbest; see the L21b header. ***
		set_variable = { name = tnt_log_n9  value = 0 }

		# --- POOL 1: the inside of your own realm ----------------------
		every_vassal = {
			save_temporary_scope_as = tnt_lean_b
			save_temporary_scope_as = tnt_thr_you
			root = { save_temporary_scope_as = tnt_thr_me }
			root = { change_variable = { name = tnt_log_n1  add = 1 } }
			tnt_log_lean_points_vassal_effect = yes

			if = {
				limit = { tnt_can_threat_trigger = { A = root  B = scope:tnt_lean_b } }
				root = { change_variable = { name = tnt_log_n4  add = 1 } }
				if = {
					limit = {
						tnt_door_open_trigger = { A = root  B = scope:tnt_lean_b }
						root = { tnt_partner_valid_trigger = { CHARACTER = scope:tnt_lean_b } }
					}
					root = { change_variable = { name = tnt_log_n7  add = 1 } }
				}
			}
			if = {
				limit = { tnt_door_open_trigger = { A = root  B = scope:tnt_lean_b } }
				root = { change_variable = { name = tnt_log_n5  add = 1 } }
			}
			if = {
				limit = { root = { tnt_partner_valid_trigger = { CHARACTER = scope:tnt_lean_b } } }
				root = { change_variable = { name = tnt_log_n6  add = 1 } }
			}
		}

		# --- POOL 2: the neighbours, LAND AND ACROSS WATER --------------
		# WIDENED 2026-08-24 in lockstep with the alert's own pool 2. The probe
		# must walk what the alert walks or nbrs= measures a set nobody uses.
		every_neighboring_and_across_water_top_liege_realm_owner = {
			save_temporary_scope_as = tnt_lean_b
			save_temporary_scope_as = tnt_thr_you
			root = { save_temporary_scope_as = tnt_thr_me }
			root = { change_variable = { name = tnt_log_n2  add = 1 } }
			tnt_log_lean_points_nbr_effect = yes

			if = {
				limit = { tnt_can_threat_trigger = { A = root  B = scope:tnt_lean_b } }
				root = { change_variable = { name = tnt_log_n4  add = 1 } }
				if = {
					limit = {
						tnt_door_open_trigger = { A = root  B = scope:tnt_lean_b }
						root = { tnt_partner_valid_trigger = { CHARACTER = scope:tnt_lean_b } }
					}
					root = { change_variable = { name = tnt_log_n7  add = 1 } }
				}
			}
			if = {
				limit = { tnt_door_open_trigger = { A = root  B = scope:tnt_lean_b } }
				root = { change_variable = { name = tnt_log_n5  add = 1 } }
			}
			if = {
				limit = { root = { tnt_partner_valid_trigger = { CHARACTER = scope:tnt_lean_b } } }
				root = { change_variable = { name = tnt_log_n6  add = 1 } }
			}
		}

		# --- POOL 3: your own lieges, all the way up -------------------
		# NEW 2026-08-24, in lockstep with the alert. Since 2026-08-28 only an
		# independent target is eligible, so this pool can contribute only its
		# independent top liege. SIZE 0 for a top liege and 1-3 for a vassal,
		# so there is no cost argument to have.
		every_liege_or_above = {
			save_temporary_scope_as = tnt_lean_b
			save_temporary_scope_as = tnt_thr_you
			root = { save_temporary_scope_as = tnt_thr_me }
			root = { change_variable = { name = tnt_log_n3  add = 1 } }
			tnt_log_lean_points_liege_effect = yes

			if = {
				limit = { tnt_can_threat_trigger = { A = root  B = scope:tnt_lean_b } }
				root = { change_variable = { name = tnt_log_n4  add = 1 } }
				if = {
					limit = {
						tnt_door_open_trigger = { A = root  B = scope:tnt_lean_b }

					}
					root = { change_variable = { name = tnt_log_n7  add = 1 } }
				}
			}
			if = {
				limit = { tnt_door_open_trigger = { A = root  B = scope:tnt_lean_b } }
				root = { change_variable = { name = tnt_log_n5  add = 1 } }
			}
			if = {
				limit = { root = { tnt_partner_valid_trigger = { CHARACTER = scope:tnt_lean_b } } }
				root = { change_variable = { name = tnt_log_n6  add = 1 } }

		}

		remove_variable = tnt_log_n9
		remove_variable = tnt_log_n1
		remove_variable = tnt_log_n2
		remove_variable = tnt_log_n3
		remove_variable = tnt_log_n4
		remove_variable = tnt_log_n5
		remove_variable = tnt_log_n6
		remove_variable = tnt_log_n7
		remove_variable = tnt_log_n8
	}

# L21b - tnt_log_lean_points_<pool>_effect     this = ONE CANDIDATE
#
# THE POINTS HALF OF L21, CALLED ONCE PER CANDIDATE FROM EACH OF THE THREE
# POOLS. Three effects and not one with a parameter, for this file's standing
# no-substitution rule: the pool name is a LITERAL inside an error_log string,
# and a parameterised log line is the shape this file has refused since L0.
# The three bodies differ in exactly one word, `pool=`.
#
# PRECONDITION, AND IT IS THE CALLER'S: scope:tnt_thr_me / scope:tnt_thr_you
# name (the player, this candidate). L21 saves them unguarded at the top of
# every iterator body - see the paragraph on that in L21's header. Nothing
# here saves a scope, so these three cannot silently disagree with the counts
# beside them.
#
# TWO STATEMENTS, AND THE SECOND WAS BROKEN FOR THREE RUNS UNTIL 2026-08-25.
#   tpbar  a plain `if` on `tnt_threat_points_value >= 100` - a NAMED VALUE
#          against a LITERAL, R7's own first legal shape, and the literal is
#          the gate's own bar rather than a second copy of it.
#   tpbest a SELF-REFERENCING set_variable over a nested block - `value = {
#          value = var:tnt_log_n9  min = tnt_threat_points_value }` - i.e.
#          max(running, this man). It USED TO BE `change_variable = { name =
#          tnt_log_n9  add = 0  min = <value> }`, which printed tpbest=0 on
#          EVERY LEAN line ever emitted while LEANC's `tp=` two lines below
#          read 3.5k-7.4M on the same scope in the same body: min/max clamp
#          INSIDE a script value, not at the top level of change_variable.
# BOTH READ THE VALUE AGAIN; three evaluations a candidate, and deliberate.
########################################################################
tnt_log_lean_points_vassal_effect = {
	if = {
		limit = { tnt_threat_points_value >= 100 }
		root = { change_variable = { name = tnt_log_n8  add = 1 } }
	}
	# THE RUNNING MAXIMUM, RESHAPED 2026-08-25 AFTER tpbest READ 0 ON EVERY LEAN
	# LINE OF EVERY RUN WHILE THE tp= TWO LINES BELOW READ REAL NUMBERS. min/max
	# are SCRIPT-VALUE operators: they clamp inside a nested `value = { }` and do
	# nothing at the top level of change_variable. Vanilla proof: L21b's header.
	root = { set_variable = { name = tnt_log_n9  value = { value = var:tnt_log_n9  min = tnt_threat_points_value } } }
	if = {
		limit = { has_game_rule = tnt_ai_telemetry_verbose }
		root = {
			set_variable = { name = tnt_log_b   value = scope:tnt_lean_b }
			set_variable = { name = tnt_log_c1  value = tnt_threat_points_value }
			error_log = "TNTLOG|v1|LEANC|y=[GetCurrentDate.GetYear]|pool=vassal|bid=[THIS.Char.MakeScope.Var('tnt_log_b').Char.GetID]|tp=[THIS.Char.MakeScope.Var('tnt_log_c1').GetValue]"
			remove_variable = tnt_log_b
			remove_variable = tnt_log_c1
		}
	}
}
