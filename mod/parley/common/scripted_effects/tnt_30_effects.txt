#   * OFFER state goes in tnt_reset_offer_effect (E3). SESSION state goes in

#     before it.

# §3.C asked for inside tnt_31_lists.txt — a file no build-3 author owns and
# which is therefore still the build-1 seven-list fan-out. Each bridge is
# idempotent, so when that file is finally updated the bridges become a
# harmless second pass and can be deleted. They are NOT optional today:
# without them tnt_list_spouse_p/_r is never built and never cleared.
#
# EVERY effect in this file runs with root = THE PLAYER (the interaction's
# scope:actor, or GuiScope.SetRoot(GetPlayer.MakeScope) from a scripted_gui).
# All tnt_* variables live on that character (33 in v1; v2 adds the six
# currency figures of item 2.4 and the two tnt_infl_ok_* mirrors).
#
# THERE ARE NO EXCEPTIONS ANY MORE. There used to be two — tnt_tribute_out /
# tnt_tribute_in, written on whichever character carried the matching tribute
# modifier — but the yearly tribute is retired and nothing writes them now.
# A pre-purge save can still hold them; they are TIMED (years = 10), expire on
# their own, and must NOT be removed by hand while their modifier lives
# (see common\modifiers\tnt_60_modifiers.txt, the shim). Nothing in this mod
# writes a variable onto any object that is not a character (R-CLEAN-2).
#
# Object-valued variables are ALWAYS read under `exists = var:x` or
# `var:x ?= { }` — the window can be closed and reopened and a target can
# die between clicks (report 04 §13.8).

# E1 — tnt_open_window_effect
#
# Called from tnt_open_negotiations' on_send, INSIDE scope:actor = { }.
# Interaction effects execute on every client, so the interaction author
# scopes to the actor and we write only actor-local variables here; the
# window's `visible` is gated on GetPlayer's own tnt_open, so no other
# client can see it. (PDX's own rule:
#  GAME\common\character_interactions\00_religious_interactions.txt:1897)
#
# Requires scope:recipient to exist. Order matters: the partner must be
# stored before tnt_refill_all_lists_effect runs, because every fill
# effect reads var:tnt_partner.
########################################################################
# AUTOPAUSE IS REMOVED ENTIRELY (user ruling: "вообще убрать автопаузу").
# Opening the deal window does NOT pause the game, by decision, after three
# engine mechanisms failed across three sessions:
#   1. message auto_pause — tnt_pause_on_open_effect + common\messages +
#      common\message_filter_types (all long deleted): the pause was lost
#      whenever the letter event's own pause channel released on close, and its
#      toast rendered raw loc keys.
#   2. OnPause from a GUI state on_start (widget tnt_pause_on_open in
#      gui\tnt_diplomacy_window.gui): fired on open but proved unreliable in
#      play.
#   3. the tnt_pause_latch rework of the same widget: the final playtest opened
#      the window with no pause set at all.
# Nothing pause-related remains script-side. Do NOT reintroduce a pause from
# this effect — a fourth attempt, if ever wanted, must start from a mechanism
# that is none of the three above.
tnt_open_window_effect = {
	set_variable = {
		name = tnt_partner
		value = scope:recipient
	}
	set_variable = {
		name = tnt_open
		value = 1
	}

	# USER ITEM 9, THE HALF THAT WAS NEVER WRITTEN, and writing it is what lets the
	# window go back to layer = middle where it belongs.
	#
	# The character window is layer = middle (GAME\gui\window_character.gui:11). So is
	# ours. Out-layering it looked like the cheap answer and it was raised to `events`
	# instead - which put it ABOVE the interaction confirmation window and the vanilla
	# matchmaker (both layer = middle) and ON the event layer, so the deal-confirmation
	# dilemma and the classic marriage screen both opened behind it. Three reported
	# faults, one line.
	#
	# Closing the view is the answer vanilla itself uses. `view = character` is real,
	# 13 call sites, bare form proven verbatim at
	# GAME\common\tutorial_lessons\00_tutorial_lessons_basics.txt:1366. The BLOCK form
	# with player = root is the shape decisions use
	# (GAME\common\decisions\00_ep1_other_decisions.txt:58-61) and it is the one to
	# prefer here: interaction effects execute on every client, and this must close a
	# window for the sender only.
	# FALLBACK TAKEN. The block form with view = character did NOT close the window -
	# reported: "it stays open and covers the deal window". Every vanilla block-form
	# call site passes view = decisions and nothing else, so the pairing of that form
	# with this view name is evidently not supported. Switched to the BARE form, which
	# IS proven verbatim for this exact view at
	# GAME\common\tutorial_lessons\00_tutorial_lessons_basics.txt:1366.
	#
	# The multiplayer caveat is accepted knowingly: the bare form takes no player
	# parameter, and interaction effects execute on every client. This effect is
	# already called from inside scope:actor = { } in the interaction's on_send, so the
	# scope is the sender - but whether the engine honours that for a view command is
	# not something the files state. In single player it is moot. If a co-op partner
	# ever reports their character window closing when someone else negotiates, this
	# line is why.
	close_view = character

	# Game-rule gate for the Tier-4 rows (marriage, title, vassal). Stored
	# as a variable so the GUI can test it with a cheap map lookup instead
	# of calling a scripted_gui from `visible` every frame (Law 9).
	if = {
		limit = { tnt_advanced_terms_trigger = yes }
		set_variable = {
			name = tnt_advanced
			value = 1
		}
	}
	else = {
		remove_variable = tnt_advanced
	}

	# =====================================================================
	# Legacy session snapshots retained for save/addon compatibility only.
	# Currency rows and controls now evaluate the canonical directional
	# predicates live; neither side's permission may rely on this cache.
	# The balancer and preflight also use live predicates, not these variables.
	if = {
		limit = { tnt_trade_prestige_trigger = { A = root  B = var:tnt_partner } }
		set_variable = {
			name = tnt_trade_prest_on
			value = 1
		}
	}
	else = {
		remove_variable = tnt_trade_prest_on
	}
	if = {
		limit = { tnt_trade_piety_trigger = { A = root  B = var:tnt_partner } }
		set_variable = {
			name = tnt_trade_pty_on
			value = 1
		}
	}
	else = {
		remove_variable = tnt_trade_pty_on
	}

	# Start from a clean table even if a previous session left residue.
	# This does NOT touch tnt_open / tnt_partner / tnt_advanced.
	tnt_reset_offer_effect = yes

	tnt_refill_all_lists_effect = yes

	# --- item 2.1: the initial line of descent -------------------------
	# REPLACES tnt_pick_marriage_pair_effect (E13). The auto-picked pair is
	# exactly what item 2.1 removes; what is still wanted at open time is a
	# sensible default for the line control, taken from the player's own
	# realm law / faith doctrine — the default branch of vanilla's
	# ai_wants_matrilineal_marriage (GAME\common\scripted_rules\00_rules.txt:678-684).
	# It runs AFTER the reset, so it can never overwrite a line the player
	# has already chosen this session.
	tnt_marriage_default_line_effect = yes

	# --- item 2.1 (iteration 4): the pair LIST ---------------------------
	# The deal is now an unlimited list of pairs, tnt_wed_list, and each pair
	# stores tnt_wed_partner + tnt_wed_matri ON THE PLAYER-SIDE SPOUSE — i.e. on
	# a character who is NOT the player. tnt_reset_offer_effect above has
	# already emptied all of it in the correct order (strip every member, THEN
	# clear the list) because tnt_reset_marriage_effect now opens with
	# tnt_wed_clear_all_effect, so this line has nothing left to clean.
	#
	# It is here anyway, and it is not decoration: tnt_wed_sync_effect is the
	# effect that keeps tnt_marriage_p / _r honest against an empty list and
	# keeps tnt_wed_principal pointing at a live member. Calling it once at open
	# time means a save written by an earlier build, or by a session that ended
	# with the panel up, arrives at a defined state instead of a plausible one.
	# It is idempotent and costs one has_variable_list plus one exists.
	tnt_wed_sync_effect = yes

	# --- item 2.1: the two candidate lists -----------------------------
	# BRIDGE REMOVED IN BUILD 3. tnt_fill_spouse_lists_effect is now the last
	# line of tnt_refill_all_lists_effect (tnt_31_lists.txt), which the line
	# above already calls, so it runs here exactly as it did — and it now also
	# runs on the two paths that were missing it, the window's _show state and
	# the AI counter-offer. Do not re-add it here: the fills are idempotent, but
	# a second copy is a second place to forget.

	# --- item 2.2: fill, THEN prune ------------------------------------
	# Idempotent hardening (NOTES3-multiselect.md M4). tnt_reset_offer_effect
	# above has just emptied every selection list, so today this costs nine
	# has_variable_list tests and nothing else. It is here so that no future
	# author has to re-derive that every fill effect opens with
	# clear_variable_list and therefore hands every already-chosen object
	# back to the "available" column: fill must always be followed by prune.
	tnt_multi_prune_all_effect = yes

	# Item 2.4: decide, once per opening, whether either side can trade
	# influence. Must come AFTER tnt_partner is set above, because the
	# partner half of the test reads it. See E2b for why this exists in two
	# places and how to collapse it to one.
	tnt_refresh_v2_mirrors_effect = yes

	#===================================================================
	# USER REQUEST NEW-2 — the row-visibility answers (35 of them since
	# user item 19; E33 owns the count).
	# *** LAST STATEMENT OF THIS EFFECT. DO NOT MOVE IT. ***
	#===================================================================
	# NOTES3-gates-interaction.md §2.1 and §3.2 call C1. Every gate reads
	# var:tnt_partner, six read var:tnt_advanced, fourteen read a picker list
	# that tnt_refill_all_lists_effect has just built (eight shipped plus item
	# 19's six people lists), and two read the two
	# spouse lists that tnt_fill_spouse_lists_effect has just built. Calling
	# this any earlier answers every one of those questions about the PREVIOUS partner —
	# which is precisely the bug that makes the second negotiation of a
	# session show the wrong rows.
	# E33 sets tnt_gate_live as its own last statement for the same reason.
	tnt_refresh_show_gates_effect = yes
	# No pause here: autopause is removed entirely (user ruling) — the full
	# record of the three failed attempts is in this effect's header comment.
}

# Cleanup is mandatory, not optional: leftover state leaks into the save
# and re-opens the window spuriously
# (MOD\3037969445\common\scripted_guis\zz_lmf_scripted_guis.txt:32-36).

# So the answer is a pair of cheap 0/1 mirror variables the GUI can test
# with one map lookup: `visible = "[TntOn('tnt_infl_ok_p')]"`.
#
# *** BUILD 2: THIS IS NOW THE ONLY COPY OF THE GOVERNMENT TEST. ***
# The first build carried the same two writes twice — here and in the body of
# the scripted_gui `tnt_refresh_v2_mirrors` (tnt_22_v2.txt, last entry) — and
# only this copy had a caller. The follow-up that file and this one asked each
# other for has been taken: that scripted_gui's body is now the single line
# `tnt_refresh_v2_mirrors_effect = yes`, and the scripted_gui

# EDIT ONLY HERE. Nothing else in the mod tests government_has_influence

# government_has_flag = government_has_influence is the test vanilla itself
# uses for its own influence send-option —

# NOTE the path: there is no `common\government_types\` directory in 1.19,

# Partner side is double-guarded (Law R13): `exists` in the limit and an
# optional link `?=` at the read.

tnt_refresh_v2_mirrors_effect = {
	# Player side. root is the player.
	if = {
		limit = { government_has_flag = government_has_influence }
		set_variable = {
			name = tnt_infl_ok_p
			value = 1
		}
	}
	else = {
		remove_variable = tnt_infl_ok_p
	}

	# Partner side. No partner => no influence row on their column.
	if = {
		limit = {
			exists = var:tnt_partner
			var:tnt_partner ?= { government_has_flag = government_has_influence }
		}
		set_variable = {
			name = tnt_infl_ok_r
			value = 1
		}
	}
	else = {
		remove_variable = tnt_infl_ok_r
	}
}

# E34 — tnt_set_show_gate_effect = { ITEM = <item>_<side> }  NEW IN BUILD 3
#
# One row of E33. The parameter builds BOTH the callee's name and the
# variable's name. $PARAM$ substitution is textual, and building a callee
# identifier out of a parameter is vanilla's own idiom. RE-VERIFIED IN THIS
# SESSION, and the second citation is not an analogy — it is this exact
# construction, a parameterised SCRIPTED TRIGGER invoked from inside a
# SCRIPTED EFFECT's `if = { limit = { … } }`:
#
#   GAME\common\scripted_effects\00_childhood_effects.txt:234-240
#       every_vassal = {
#           if = {
#               limit = {
#                   save_good_$RELATION$_character_trigger_check = yes
#               }
#               add_to_list = good_child_relation_character
#           }
#   resolving to four real triggers at
#   GAME\common\scripted_triggers\00_childhood_triggers.txt:51, 68, 93, 121
#   (save_good_friend_ / _crush_ / _bully_ / _victim_character_trigger_check),
#   with the four legal $RELATION$ values written out in that effect's own
#   header at :11-14.
#
#   The same idiom in a script value's modifier block:
#   has_$SKILL$_education_affinity_childhood_trait_trigger = yes
#     GAME\common\scripted_effects\00_education_effects.txt:361, resolving to
#     the five real triggers at
#     GAME\common\scripted_triggers\00_education_triggers.txt:195, 202, 209, 216, 223.
#
# The legal $ITEM$ values are the 25 LIVE tnt_set_show_gate_effect lines of
# E33 above (24 items plus the threat show-gate), and every one of them has a
# matching tnt_show_<item>_<side>_trigger — 17 of them in
# common\scripted_triggers\tnt_41_gates.txt and item 19's eight in
# common\scripted_triggers\tnt_42_people_gates.txt (25 ITEM lines, 25
# trigger definitions — no orphan on either side). It was 35 / 27 / 35 until
# the two retired term families took four ITEM lines and four triggers out
# together, and V13 user item 1 took SIX more the same way (alliance_p/_r with
# T22/T23, truce_p/_r with T24/T25, claim_p/_r with T30/T31); that pairing is
# what "no orphan on either side" means here.
#
# scope:tnt_gate_partner may not exist (no partner yet). Every one of the
# tnt_show_* triggers carries its own `trigger_if = { limit = { exists =
# $OTHER$ } … }` plus `trigger_else = { always = no }`, so with no partner
# every gate is false and every variable is removed — which is correct,
# because with no partner there is no window either. Item 19's eight must
# keep that shape too, or a window opened with no partner errors instead of
# hiding.
#
# remove_variable on an absent variable is silent and is what vanilla does —
# GAME\common\scripted_effects\00_scripted_effects.txt:61-62.
########################################################################
tnt_set_show_gate_effect = {
	if = {
		limit = {
			tnt_show_$ITEM$_trigger = { OTHER = scope:tnt_gate_partner }
		}
		set_variable = {
			name = tnt_show_$ITEM$
			value = 1
		}
	}
	else = {
		remove_variable = tnt_show_$ITEM$
	}
}
