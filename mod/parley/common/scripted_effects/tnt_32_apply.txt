# PARLEY: THE NEGOTIATING TABLE — deal execution
#
# Legacy effect registry E14..E28 (E16 and E19 are deleted), plus the
# preflight-support pair PF1/PF2 at the end of this file. PF names avoid
# colliding with retired E29 and the live E30..E34 families in other files.
#
# THIS IS THE FILE THAT CAN CORRUPT A SAVE. Precision beats cleverness.
#
# Root is always THE PLAYER. Every offer variable and every offer variable
# LIST lives on the player, on both sides, so every guard reads
# `var:tnt_<item>_<side>` (or `has_variable_list = tnt_sel_<item>_<side>`) in
# root scope and only the *effects* are re-scoped to the giver or the receiver.
# Build 3 raised the count from v1's 24 to ~46 variables + 16 lists; the
# authoritative registry is 30-V2-DESIGN §3, and the removal path for every
# single one of them is in tnt_30_effects.txt (E2 for session state, E3 for
# offer state).
#
# THIS IS ALSO ONE OF THE TWO INTEGRATION POINTS (R19). The bodies of the
# build-3 legs live in the authors' own files — tnt_34_marriage.txt,
# tnt_35_multiselect.txt, tnt_36_hooks_contracts.txt — and item 19's four
# people terms live in tnt_3a_people.txt beside the candidate lists that
# feed them; all of them are reached from here. Nothing in
# tnt_38_ai_world.txt is: those legs are parameter machines
# with no meaningful root and cannot be hung off a variable-driven effect.
#
# scope:tnt_deal_partner is the negotiating partner. It is saved by the
# tnt_send_offer scripted_gui
# (`var:tnt_partner ?= { save_scope_as = tnt_deal_partner }`) immediately
# before trigger_event, and travels with the event into these effects.
#
# *** WHY THE NAME IS tnt_deal_partner AND NOT tnt_p — DEFECT D4 ***
# (30-V2-DESIGN §9 D4; observed error, events/tnt_events.txt:84 and :98)
#   "[jomini_eventscope.cpp:565]: Trying to add the temporary target 'tnt_p'
#    which has the same name as a permanent target"
# tnt_send_offer saves a PERMANENT scope so it survives into trigger_event,
# while EVERY script value in the balance chain opens with contract R0.4's
# prologue `var:tnt_partner ?= { save_temporary_scope_as = tnt_p }`
# (tnt_50_values.txt:448 and ~50 further sites). The event's two option
# triggers evaluate tnt_ai_accept_value, so both lifetimes met under one
# name; the engine refused the temporary one and the values silently read
# the permanent scope instead. It happened to be the same character, which
# is why nothing looked broken.
# The PERMANENT scope was renamed (23 sites in three files) rather than the
# temporary one (~60 sites across the two value files, which waves 1a, 3a-3e
# and 4a all touch). The two value files keep `tnt_p` untouched.
# RENAMED IN LOCKSTEP — do not break these:
#   MOD\common\scripted_guis\tnt_20_scripted_guis.txt:934  save_scope_as
#   MOD\events\tnt_events.txt:66, :75
#   MOD\localization\{english,russian}\tnt_l_*.yml  tnt_confirm_desc, which
#     prints the scope as [tnt_deal_partner.GetShortUIName]
#
# The caller-side preflight validates the COMPLETE package before the first
# consequence can run, and the master repeats that gate as defence in depth.
# Every exec effect still keeps its own guard: those local checks protect
# direct/test calls and world changes caused by an earlier leg of this same
# treaty, but they are no longer the mechanism that decides whether a stale
# package may begin executing.
#
# Side suffixes (contract R0.1): _p = the PLAYER gives it, _r = the PARTNER
# gives it. Items that are mutual by nature (alliance, truce, marriage)
# appear in both columns but must fire EXACTLY ONCE, so their exec effects
# take no SIDE parameter and test both variables.
#
# $PARAM$ substitution is textual, which is why `var:tnt_gold_$SIDE$`
# resolves correctly.

# E14 — tnt_apply_deal_effect  *** THE MASTER EFFECT ***
#
# Called from the manual confirmation and the two AI-letter pay/accept paths,
# never from a scripted_gui effect directly: those fire instantly with no
# confirmation dialog and this is irreversible. Vanilla routes irreversible
# scripted_gui actions through trigger_event for exactly this reason
# (GAME\common\scripted_guis\00_religion.txt:64-67, "#Are you sure?").
#
# The event option's tooltip is generated by running this whole effect in
# tooltip mode, so the player reads the complete deal before committing.
#
# Order of the calls is the frozen contract order (item index, _p before
# _r) — 10-CONTRACT §R0.1 freezes the twelve v1 indices and the values, GUI
# and loc files quote them, so the banners are NOT renumbered even where a
# different order would read better.
#
# WHAT THE ORDER GUARANTEES, precisely, so nobody has to re-derive it:
#   * every one-time RESOURCE transfer (gold, prestige, piety, influence)
#     happens before anything else, so a payer cannot be bankrupted by an
#     earlier leg of the same treaty;
#   * FEALTY (item 12) and its CONTRACT SHEET (12b) are last, in that order,
#     because a subject contract does not exist until
#     resolve_title_and_vassal_change has run — and item 19's GRANT
#     INDEPENDENCE is inserted immediately ABOVE fealty, never below it
#     (integration contract C5, argued at the call lines themselves);
#   * item 19's COURT-MOVING terms (courtiers and hostage; the ward was the
#     third until V16 user item 5 retired it, TOMBSTONE W) sit
#     above every realm-graph leg, because a court transfer between two
#     realms needs the two realms to still be two realms;
#   * TITLE hand-over is item 6 and therefore precedes hooks and artifacts.
#     That ordering is safe because artifacts belong to characters and hooks
#     do not require land. The dangerous old combination was title cession
#     plus fealty or independence: an early cession could invalidate the later
#     realm leg after resources had already moved.
#   * the central preflight now rejects every staged title_p/title_r object or
#     selected-title list combined with either vassal_p/vassal_r or
#     indep_p/indep_r. This conservative cross-term rule removes that
#     self-invalidation without pretending to project a future realm graph.
#   * EVERY leg still re-validates its own precondition inside its own `limit`.
#     Those guards are defence in depth after the package-level gate, not a
#     licence to begin executing a package with a known invalid term.
#
#
# Guarded on partner presence/aliveness AND the complete pure preflight: a
# saved scope survives death, while a staged object or purse can go stale.
# No consequence begins unless every row passes in one world state.
#
#=======================================================================
# *** THIS EFFECT IS THE PROJECT'S SERIALISATION POINT (30-V2-DESIGN §7.1) ***
#=======================================================================
# Every new deal item must add its exec call to the list below, and that
# list is the ONE place in the mod that several parallel authors would
# otherwise collide on. Rules for whoever appends next:
#
#   * Do NOT renumber the existing comment banners. The twelve v1 item
#     indices (1..12) are frozen in 10-CONTRACT §R0.1 and are quoted by the
#     values, GUI and loc files. New one-time resource transfers go in the
#     "1b" block; anything else goes in the RESERVED block near the bottom,
#     which lists exactly which wave-3 item owns which line.
#   * Keep the two-line _p / _r shape. Every exec effect takes SIDE plus the
#     scopes it needs, and every exec effect guards itself, so this list
#     never needs a per-item `if`.
#   * root is ALWAYS the player and scope:tnt_deal_partner is ALWAYS the
#     other ruler, on both the manual path and the planned AI path
#     (30-V2-DESIGN §6.2 Option A), so the two arguments never change.
#   * Anything whose tooltip would read a variable that only exists at apply
#     time must be wrapped in hidden_effect INSIDE its own exec effect, not
#     here — that is defect D5.
########################################################################
tnt_apply_deal_effect = {
	if = {
		limit = {
			exists = scope:tnt_deal_partner
			scope:tnt_deal_partner = { is_alive = yes }
			tnt_deal_preflight_trigger = { PLAYER = root  PARTNER = scope:tnt_deal_partner }
		}

		#===============================================================
		# TELEMETRY (v3 iteration 7). Body in tnt_3b_log.txt L18, behind the
		# tnt_ai_telemetry game rule, which ships OFF - at that setting this is one
		# has_game_rule lookup.
		#
		# IT MUST BE THE FIRST THING IN THIS BRANCH, before any exec leg runs. The
		# exec legs consume and clear the term variables, so a log call placed after
		# them would report an empty package. This position is also why the line
		# describes what is ABOUT to be applied rather than what was.
		#
		# *** THIS SINGLE CALL COVERS BOTH PATHS, AND THAT IS THE POINT. *** This
		# effect's own header states that root is always the player and
		# scope:tnt_deal_partner always the other ruler "on both the manual path and
		# the planned AI path", so one call site instruments the player's Propose
		# button AND the AI's accepted letter. The APPLY line's src field tells them
		# apart on a fact already present on the character - var:tnt_ai_offer_arch
		# exists only on the AI path - and it carries tnt_ai_accept_value for the
		# package either way. That is what makes the brief's comparison possible:
		# the AI's pricing of its own deals against its pricing of the player's.
		#===============================================================
		tnt_log_apply_effect = yes

		#===============================================================
		# USER ITEM 9 — THE MEMORY OF A GOOD BARGAIN (the favour grant).
		#
		# A treaty that closes at a positive headline leaves the partner
		# better disposed toward the player: +1 opinion per headline point,
		# decaying, stacking, the stacked total capped at +50 by the
		# modifier itself — tnt_treaty_favor_opinion, whose entry in
		# common\opinion_modifiers\tnt_61_opinions.txt carries the full
		# anti-farm and threat-interaction arithmetic.
		#
		# IT SITS HERE, after the telemetry and before any exec leg, for
		# the telemetry's own reason: the legs consume and clear the term
		# variables, so tnt_ai_accept_value read after them prices an empty
		# package. This block only READS the package, so the telemetry line
		# above keeps its "first in this branch" guarantee.
		#
		# THE AMOUNT IS THE HEADLINE MINUS THE PRESSURE ROWS. Threat and
		# called-in-hook points moved the scales by fear and obligation,
		# not goodwill — a partner moved by intimidation must not also come
		# to love you, or threatening becomes friendship farming. A deal
		# carried entirely by pressure clamps to 0 and grants nothing.
		# (tnt_val_usehook_r_value is NOT subtracted: that row is negative
		# — his own leverage spent on us — and already lowered the
		# headline.)
		#
		# THE > 0 GATE ALSO MATTERS ON THE LETTER PATH: its accept option
		# tolerates a headline that drifted down to -14 ("he keeps his
		# word", events\tnt_ai_events.txt:507), and a soured deal must not
		# still hand out favour. On that same path the proposer earns the
		# favour of his own settled offer (typically +1..+15 by the settle
		# band) — accepted knowingly, audit item 9. The AI<->AI sandbox
		# never reaches this effect (banner 4b below), so the reward is
		# player-facing by construction.
		#
		# NOT in hidden_effect, on purpose: the confirm tooltip advertises
		# the "+N opinion" line as part of the consequence list. The engine
		# resolves save_scope_value_as at tooltip time — proof is
		# GAME\common\scripted_effects\00_diarchy_scripted_effects.txt:1055-1068,
		# where the saved value is consumed INSIDE show_as_tooltip.
		#
		# EVERY SHAPE IS VANILLA'S, VERBATIM:
		#   * inline clamp math in save_scope_value_as —
		#     GAME\common\character_interactions\10_tgp_interactions.txt:500-509;
		#     round = yes inside it —
		#     GAME\common\scripted_effects\00_diarchy_scripted_effects.txt:1055-1062.
		#   * save-then-spend as an add_opinion amount in one effect —
		#     GAME\common\character_interactions\00_diarch_interactions.txt:6667-6682
		#     (opinion = scope:opinion_gain), itself an on_accept that
		#     renders as a tooltip; a named-value amount —
		#     GAME\common\character_interactions\09_mpo_interactions.txt:8096-8101.
		#   * a saved value scope read in a limit —
		#     GAME\common\scripted_effects\00_laamp_effects.txt:456
		#     (`limit = { scope:gold > 0 }`); exists on a value scope —
		#     GAME\events\interaction_events\character_interaction_events.txt:1840.
		#     The exists row is belt-and-braces against defect D5's class:
		#     if tooltip mode ever skips the save, the branch hides instead
		#     of erroring on a missing scope.
		#
		# DIRECTION: add_opinion runs on the holder of the feeling, so the
		# PARTNER's opinion of the PLAYER rises — root is always the player
		# in this effect (header) — mirroring the diarch site above.
		#===============================================================
		if = {
			limit = {
				tnt_ai_accept_value > 0
				# *** A DEMAND IS NOT A BARGAIN, AND IT MUST NOT BUY GOODWILL. ***
				# V30 skeptic. The demand letter's PAY option runs this same apply
				# effect, and on that path gain = the extorted gold while loss = 0,
				# so tnt_ai_accept_value is strongly positive and this block would
				# hand the extortioner a POSITIVE opinion of his victim - the mod
				# thanking the player for having been robbed. The two subtract rows
				# below already strip threat and use-hook out of the favour for
				# exactly this reason on the manual path; arch 21 is the same idea
				# one level up, where the WHOLE treaty is the coercion.
				# R13: the exists row guards the read, so a manual treaty - which
				# carries no archetype variable at all - simply passes.
				NOT = {
					AND = {
						exists = var:tnt_ai_offer_arch
						var:tnt_ai_offer_arch = 21
					}
				}
			}
			save_scope_value_as = {
				name = tnt_treaty_favor
				value = {
					value = tnt_ai_accept_value
					subtract = tnt_val_threat_p_value
					subtract = tnt_val_usehook_p_value
					min = 0
					max = 50
					round = yes
				}
			}
			if = {
				limit = {
					exists = scope:tnt_treaty_favor
					scope:tnt_treaty_favor > 0
				}
				scope:tnt_deal_partner = {
					add_opinion = {
						modifier = tnt_treaty_favor_opinion
						target = root
						opinion = scope:tnt_treaty_favor
					}
				}
			}
		}

		#===============================================================
		# USER ITEM 21 — THE CONSCIENCE OF THE SIGNATORY (the stress leg).
		#
		# *** V30 RESTATES THIS BANNER FOR THE NEW SHAPE. FIVE ARMS, NOT TWO
		# *** LEGS; stress_impact, NOT add_stress; GROSS, NOT NET. ***
		# The body is tnt_stress_deal_effect (tnt_3c_stress.txt), and the whole
		# argument for every one of those three changes lives in that file's
		# header. What a reader standing HERE needs to know is only this:
		#   * ONE ARM EXECUTES, so at most one stress line is rendered and at
		#     most one charge is applied, exactly as before - the enforcement
		#     is still an if / else_if ladder.
		#   * THE ARMS ARE: A force was used (a threat was ticked, or a hook
		#     was actually called in); B I gave heavily, at two rungs; C I
		#     took heavily, at two rungs. B beats C on a treaty that is large
		#     both ways, deliberately, because vanilla prices the giving hand
		#     and never nets.
		#   * THE CHARGE CAN NOW BE NEGATIVE. A generous ruler who hands the
		#     shop over is RELIEVED, which is vanilla's own reading of the
		#     trait (00_gift.txt:159-161,
		#     00_grant_titles_interaction.txt:884-889). Ceiling +100, floor
		#     -60. "The treaty can reduce stress" has never shipped before.
		#   * THE LINE IN THE CONFIRM TOOLTIP NOW NAMES THE TRAITS, in nine
		#     languages, for zero new localization keys - "You gain 60 stress
		#     because you are Greedy and Ambitious". That is the whole reason
		#     the mechanism was swapped.
		#
		# SLOT 4 IS PLACED ABOVE THE EXEC LEGS FOR THE SAME REASON AS SLOT 3,
		# AND THE REASON IS STRONGER UNDER THE GROSS MEASURE, NOT WEAKER.
		# The exec legs consume and clear the term variables, so anything
		# that PRICES the package must run before them: read one line lower
		# and tnt_stress_gave_value and tnt_stress_took_value would both
		# measure an empty treaty - i.e. read 0 - and no arm below A could
		# ever fire. That is the telemetry line's
		# argument (banner at the top of this branch) and the favour block's,
		# and it is why the two consequence blocks sit together here rather
		# than at the end where "consequences" would read more naturally.
		# *** DO NOT MOVE THIS CALL. ***
		#
		# FAVOUR FIRST, STRESS SECOND — integration contract §4 C3. The
		# favour block is the older, shipped one and its position is already
		# argued above; stress goes immediately after so the confirm tooltip
		# prints the two consequences in the order the player will read them:
		# "he will remember this", then "this will weigh on you".
		#
		# THEY DO NOT DOUBLE-PUNISH, and the check has been made. The favour
		# block already subtracts tnt_val_threat_p_value AND
		# tnt_val_usehook_p_value, so a treaty taken by force grants less
		# goodwill; this block then charges the player's
		# own conscience. Two different ledgers — the partner's memory and
		# the player's mind — and NEITHER READS THE OTHER'S OUTPUT. Only the
		# first of them is part of the balance model.
		# V30 KEEPS THAT TRUE FOR THE HOOK TOO. Arm A now fires on a spent
		# hook as well as on a threat (ruling 2), and the favour block above
		# has ALWAYS subtracted the use-hook row, so the two ledgers still
		# read the same act from opposite sides without either reading the
		# other's output. The gross measures arms B and C read are the two
		# column totals, and threat and use-hook are outside both of them by
		# written design (tnt_57_threat_values.txt:14-23), so no act is
		# priced twice by the stress layer either.
		#
		# The body is guarded whole by NOT = { exists = scope:tnt_deal_from_letter }
		# — the manual path only, argued in full in tnt_3c_stress.txt — and
		# is deliberately NOT in hidden_effect, because the stress line
		# belongs in the confirm tooltip. Everything it reads is pure, so it
		# is tooltip-safe (defect class D5).
		#
		# *** DO NOT "RESTORE" var:tnt_ai_offer_arch HERE. *** This comment named
		# that variable until V18 and it named the BUG: tnt_ai_offer_arch is
		# days = 200 for the GC's sake while a letter may sit unanswered for
		# years, so from day 201 the guard silently expired and the accept
		# tooltip grew stress lines for taking the AI's own bargain — V7b
		# defect 1, tnt_3c_stress.txt:140-152 (the range read :60-79 until V30,

		# V18 then moved the guard again,
		# off var:tnt_ai_letter and onto a SAVED SCOPE VALUE written by the

		# "THIS deal came from a letter" — an unanswered letter in the feed was
		# switching the whole layer off for every manual treaty signed while it
		# sat there. A saved scope value cannot outlive its own execution, so
		# the guard is now correct by construction.
		#===============================================================
		tnt_stress_deal_effect = yes

#

# Atomic, tooltipped in both directions, and it respects the short-term
# income budget the AI uses. The two blacklisted gold-moving names
# (00-ARCHITECTURE §4.6) must never be used instead.
# `gold = <scope>.var:x` is vanilla —
# GAME\common\decisions\80_major_decisions.txt:2305-2308 uses gold = var:x.
########################################################################
tnt_exec_gold_effect = {
	if = {
		limit = {
			exists = var:tnt_gold_$SIDE$
			var:tnt_gold_$SIDE$ > 0
		}
		$GIVER$ = {
			pay_short_term_gold = {
				gold = root.var:tnt_gold_$SIDE$
				target = $RECEIVER$
			}
		}
	}
}

# E20 — tnt_exec_title_effect       params: SIDE, GIVER, RECEIVER
#
# The canonical 3-step title hand-over, in ONE effect that is called
# EXACTLY ONCE per side. Mis-sequencing it — forgetting resolve_, or
# resolving twice — produces corrupt vassal states.
#   1. create_title_and_vassal_change = { type = granted save_scope_as = X }
#      in the GIVER's scope
#   2. <title> = { change_title_holder = { holder = RECEIVER change = X } }
#   3. resolve_title_and_vassal_change = X
# Verbatim pattern GAME\common\character_interactions\00_invite_agent_to_scheme.txt:195-229;
# the two optional keys used below are shown at
# GAME\common\character_interactions\00_tradition_interactions.txt:368-385
# and GAME\common\character_interactions\00_character_interactions.txt:2310-2319.
#
# `type = granted` is the correct type for a negotiated hand-over
# (119 vanilla uses).
#
# The on-loss key below is set to yes so the former holder keeps a claim,
# which is the Total-War-appropriate outcome and keeps the AI honest.
# NOTE FOR THE VERIFIER: that key is the ONLY line in this mod that a naive
# substring grep for the blacklisted short claim-effect name will hit. It is
# a genuine parameter of create_title_and_vassal_change, not the blacklisted
# effect. Do not delete it. See NOTES-effects.md.
#
# SAME-PAIR ANCHOR, V16 - this closes NOTES-effects.md open item 2, which asked
# for a vanilla site carrying `add_claim_on_loss` and `take_baronies` on the SAME
# create/change pair. Both pairings exist:
#   yes + yes (the CONQUEST pairing this leg used to ship):
#     GAME\common\scripted_effects\07_frankokratia_scripted_effects.txt:889-899
#     (ep3_frankokratia_give_financier_sate_lands_effect)
#   yes + no  (the NEGOTIATED pairing this leg ships now):
#     GAME\events\yearly_events\yearly_events_7.txt:1393-1403
#     (create_title_and_vassal_change = { type = granted  add_claim_on_loss = yes }
#      then every_in_list = { change_title_holder = { take_baronies = no } })
# The mod now matches yearly_events_7.txt:1393-1403 verbatim.
#
# The change scope name carries the side suffix so the two calls in
# tnt_apply_deal_effect can never collide.
#
# The title is re-validated against tnt_can_cede_title_trigger here: it may
# have changed hands, become the giver's primary title or become their
# capital since it was picked.

tnt_exec_title_effect = {
	if = {
		limit = {
			exists = var:tnt_title_$SIDE$
			var:tnt_title_$SIDE$ ?= { tnt_can_cede_title_trigger = { GIVER = $GIVER$ } }
		}

		var:tnt_title_$SIDE$ ?= { save_scope_as = tnt_ceded_$SIDE$ }

		if = {
			limit = { exists = scope:tnt_ceded_$SIDE$ }

			$GIVER$ = {
				create_title_and_vassal_change = {
					type = granted
					save_scope_as = tnt_change_$SIDE$
					add_claim_on_loss = yes
				}
			}

			# V16, USER ITEM 1 - kept identical to the live window leg
			# (tnt_35_multiselect.txt M6) so the dormant leg cannot drift from it.
			# `take_baronies = no` is vanilla's NEGOTIATED value; the iterator
			# moves only the baronies the GIVER holds himself and that are not
			# leased out, so mayors, lay-clergy temple holders and leased
			# bishoprics keep their seats. Vanilla anchors, in full at M6:
			# GAME\common\casus_belli_types\00_event_war.txt:638-658,
			# GAME\common\on_action\title_on_actions.txt:2302-2318,
			# GAME\common\important_actions\00_realm_actions.txt:218-222,
			# GAME\common\scripted_effects\00_petition_liege_effects.txt:1229-1256.
			scope:tnt_ceded_$SIDE$ = {
				if = {
					limit = { tier = tier_county }
					hidden_effect = {
						every_in_de_jure_hierarchy = {
							limit = {
								tier = tier_barony
								holder ?= $GIVER$
								is_leased_out = no
								# Same engine refusal as the live leg - see the long note in
								# common\scripted_effects\tnt_35_multiselect.txt beside this row.
								is_capital_barony = no
							}
							change_title_holder = {
								holder = $RECEIVER$
								change = scope:tnt_change_$SIDE$
							}
						}
					}
				}
				change_title_holder = {
					holder = $RECEIVER$
					change = scope:tnt_change_$SIDE$
					take_baronies = no
				}
			}

			$GIVER$ = {
				resolve_title_and_vassal_change = scope:tnt_change_$SIDE$
			}
		}
	}
}

# E23 — tnt_exec_hook_effect        params: SIDE, GIVER, RECEIVER
#
# Reuses vanilla's ready-made guarded wrapper rather than a bare add_hook,
# so the can_add_hook check is never forgotten —
# GAME\common\scripted_effects\00_hook_effects.txt:28-41
#   add_hook_if_possible_default_length_effect = { TARGET = ... TYPE = ... }
# favor_hook is a real hook type (GAME\common\hook_types\00_hook_types.txt:16,
# weak, 3650 days).
#
# *** DIRECTION ***  add_hook run in scope Y with target = X means
# "Y gains a hook OVER X" — GAME\common\character_interactions\00_grant_titles_interaction.txt:1065-1077,
# where scope:actor (who granted the title, i.e. did the favour) gains the
# hook on scope:recipient.
# The deal item reads "Owe the other party a favour they may call in", so
# the side that GIVES this term must end up owing: the RECEIVER gains the
# hook and the GIVER is the one hooked. The parameters therefore appear
# swapped relative to the other exec effects — that is deliberate.
# See NOTES-effects.md.
#
#=======================================================================
# BUILD 3 — ITEM 2.3, HOOK TIERS. BODY SWAPPED, NAME AND PARAMETERS KEPT.
#=======================================================================
# tnt_hook_p / tnt_hook_r are no longer 0/1 flags: they are 0..3 TIER indices
# (0 none, 1 favour, 2 strong, 3 eternal) and the hook TYPE varies per tier —
# tnt_deal_favor_hook / tnt_deal_strong_hook / tnt_deal_eternal_hook, all
# three declared additively in common\hook_types\tnt_90_hook_types.txt.
# The whole ladder therefore lives in ONE place,
# tnt_exec_hook_tier_effect (tnt_36_hooks_contracts.txt:83), and this effect
# forwards its three parameters unchanged.
#
# The RESERVED banner of tnt_apply_deal_effect prescribed exactly this — a
# body swap, not a new call — so that the two hook call lines under "item 9"
# never move. W-12 in 30-V2-DESIGN §3.2 is the coordinated-edit list, and this
# is its apply-side entry.
#
# EVERYTHING ABOVE THIS BOX STILL APPLIES, in particular the DIRECTION rule:
# the receiver gains the hook and the giver is the one hooked. The tier effect
# reproduces that argument order.
#
# CARRIES OPEN RISK R-2: the additivity of common/hook_types/ rests on one
# installed 1.19 mod plus DB convention and is not runtime-verified. After the
# first tier-2 or tier-3 hook, exit the game and grep error.log for
# "Unknown hook type" and tnt_deal_. Named fallback: vanilla's own
# favor_hook / strong_favor_hook / strong_obligation_hook, one TYPE per branch
# inside tnt_exec_hook_tier_effect, and delete the new file.
########################################################################
tnt_exec_hook_effect = {
	tnt_exec_hook_tier_effect = { SIDE = $SIDE$  GIVER = $GIVER$  RECEIVER = $RECEIVER$ }
}


########################################################################
# E24 — tnt_exec_artifact_effect    params: SIDE, GIVER, RECEIVER
#
# set_owner in the ARTIFACT's scope. The two blacklisted artifact-moving
# names do not exist. Full form with a history
# entry so the artifact's own history reads correctly afterwards —
# verbatim call site
# GAME\common\character_interactions\10_tgp_interactions.txt:8473-8485.
#
# Re-validated against tnt_artifact_giftable_trigger: the artifact may have
# changed owner, been destroyed or become unclaimable since it was picked.
########################################################################
tnt_exec_artifact_effect = {
	if = {
		limit = {
			exists = var:tnt_artifact_$SIDE$
			var:tnt_artifact_$SIDE$ ?= { tnt_artifact_giftable_trigger = { RECEIVER = $RECEIVER$ } }
		}
		var:tnt_artifact_$SIDE$ ?= {
			set_owner = {
				target = $RECEIVER$
				history = {
					type = given
					actor = $GIVER$
					recipient = $RECEIVER$
					location = $GIVER$.location
				}
			}
		}
	}
}

# E26 — tnt_exec_vassal_effect      params: SIDE, LIEGE, VASSAL
#
# THE HIGHEST-RISK EFFECT IN THE MOD. This is a copy of vanilla's
# offer_vassalization_interaction_effect
# (GAME\common\scripted_effects\00_interaction_effects.txt:2130-2226) with
# only two changes:
#   scope:actor     -> $LIEGE$
#   scope:recipient -> $VASSAL$
# and the scope name `change` -> `tnt_vassal_change_$SIDE$` so two calls
# cannot collide. The high_obligations / low_obligations /
# religious_exemption / religious_exemption_clan branches are dropped
# because we never set those scope values, so only vanilla's `else` branch
# (feudal_government_taxes 2, feudal_government_levies 2) survives.
#
# The two blacklisted one-line fealty effect names DO NOT EXIST. The real
# machinery is create_title_and_vassal_change { type = swear_fealty } +
# change_liege + resolve_title_and_vassal_change.
#
# *** THE GUARD THAT MUST NOT BE REMOVED ***
#   hidden_effect = { if = { limit = { top_liege != this } ... } }
# around vassal_contract_set_obligation_level, with vanilla's own comment
# reproduced verbatim. The contract does not exist yet while the tooltip is
# being generated; without this guard error.log is spammed on every single
# tooltip build (00_interaction_effects.txt:2158).
#
# custom_tooltip = normal_obligations_taxes / normal_obligations_levies are
# VANILLA loc keys, reused as-is.
#
# Re-validated through tnt_can_vassalize_trigger, which folds the
# cross-character tier comparison into a script value (contract R0.3).
########################################################################
tnt_exec_vassal_effect = {
	if = {
		limit = {
			exists = var:tnt_vassal_$SIDE$
			var:tnt_vassal_$SIDE$ > 0
			tnt_can_vassalize_trigger = {
				LIEGE = $LIEGE$
				VASSAL = $VASSAL$
			}
		}

		$LIEGE$ = {
			create_title_and_vassal_change = {
				type = swear_fealty
				save_scope_as = tnt_vassal_change_$SIDE$
			}
		}

		$VASSAL$ = {
			change_liege = {
				liege = $LIEGE$
				change = scope:tnt_vassal_change_$SIDE$
			}
			add_opinion = {
				modifier = became_vassal
				target = $LIEGE$
				opinion = 10
			}
		}

		$LIEGE$ = {
			resolve_title_and_vassal_change = scope:tnt_vassal_change_$SIDE$
		}

		# Special terms for feudal contracts
		$VASSAL$ = {
			if = {
				limit = {
					government_has_flag = government_is_feudal
				}
				hidden_effect = {
					if = {
						limit = { top_liege != this } # To avoid errors during tooltip generation (prior to the contract being generated)
						vassal_contract_set_obligation_level = { type = feudal_government_taxes level = 2 }
						vassal_contract_set_obligation_level = { type = feudal_government_levies level = 2 }
					}
				}

				#=======================================================
				# BUILD 3 — THE TWO custom_tooltip LINES THAT WERE HERE
				# ARE DELETED. DO NOT PUT THEM BACK.
				#=======================================================
				# They were an unconditional
				#     custom_tooltip = normal_obligations_taxes
				#     custom_tooltip = normal_obligations_levies
				# pair. tnt_exec_obligations_effect
				# (tnt_36_hooks_contracts.txt:667-740), which
				# tnt_apply_deal_effect now calls immediately after this
				# effect, ALWAYS prints exactly one tax line and one levy
				# line for a feudal subject — including the
				# untouched-sheet case, whose `else` branches print these
				# very two vanilla keys (:700, :733). Keeping the pair
				# here would show the player two contradictory tax lines
				# the moment the contract sheet is used.
				#
				# The hidden_effect above STAYS. It is the fallback that
				# keeps a plain fealty at taxes 2 / levies 2 if the two
				# tnt_exec_obligations_effect lines in tnt_apply_deal_effect
				# are ever reverted, and vanilla's own comment inside it is
				# the tooltip-time guard, not decoration.
				# If those two lines ARE reverted, restore the two
				# custom_tooltip lines in the same commit or a plain
				# vassalisation says nothing about its own contract.
			}
		}

		# Struggle catalysts.
		hidden_effect = {
			fp3_struggle_apply_independent_vassalage_catalyst_effect = {
				NEW_LIEGE = $LIEGE$
				NEW_VASSAL = $VASSAL$
			}
		}
	}
}

# tnt_result = 1 drives the in-window banner; the toast is the out-of-window
# feedback. send_interface_toast shape verbatim from

		value = 1
	}

	# (00_character_interactions.txt:2216, 00_marriage_interactions.txt:3595,

	hidden_effect = {
		if = {
			limit = { exists = scope:tnt_deal_partner }
			send_interface_toast = {
				type = event_toast_effect_good
				title = tnt_msg_accepted
				left_icon = root
				right_icon = scope:tnt_deal_partner
				custom_tooltip = tnt_toast_tt
			}
		}
	}
}
