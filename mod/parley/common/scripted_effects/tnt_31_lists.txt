# PARLEY: THE NEGOTIATING TABLE — picker list construction + promise garbage collection
#
# Contract 10-CONTRACT.md §6.1, effects E4..E12 and E29.
#
# There is NO engine datamodel for a character's titles, claims or
# artifacts — the two blacklisted `Character.Get*` datafunctions people
# expect were searched across all ~200 vanilla .gui files and do not exist —
# so every picker is fed by a script-built variable LIST that the GUI reads
# with GetPlayer.MakeScope.GetList('<name>') and unwraps with Scope.Title /
# Scope.Artifact / Scope.Char.
#
# All 15 candidate lists live ON THE PLAYER, whichever side they describe, so
# the GUI always reads them off GetPlayer. Every fill effect therefore
# saves the player as scope:tnt_list_owner and writes into that scope from
# inside the iterator — the vanilla idiom, verbatim shape from
#   GAME\common\scripted_effects\00_funeral_scripted_effects.txt:5-33
#     clear_variable_list = $LIST_NAME$
#     save_scope_as = list_scope
#     every_X = { limit = { ... }
#         scope:list_scope = { add_to_variable_list = { name = ... target = prev } } }
# `target = prev` inside the re-scoped block resolves to the iterated
# object, which is exactly what we want stored.
#
# ONE DELIBERATE DEPARTURE from that vanilla snippet: every scope here is
# saved with save_temporary_scope_as, not save_scope_as. The scopes are
# dereferenced only inside the same effect invocation, and a permanent
# save_scope_as would serialise tnt_*-named scopes into the savegame that
# tnt_close_window_effect has no way to remove. That matters most in
# tnt_gc_promises_effect (E29) - which is RETIRED V12: tombstone header at
# :773, dead body from :815. History, never a live yearly walk. (2026-08-24)
#
# MakeScope.GetList is a persistent save-game variable list, not a live
# query, so the lists are rebuilt on window open, on window _show, when a
# picker panel is opened, and after a title changes hands.
#
# THE PRISONER PARAGRAPH THAT STOOD HERE IS RETIRED WITH ITS TERM. It explained why
# the captive picker needed a script list at all: a datamodel cannot answer "am I
# already chosen?" - the engine has no list-membership datafunction - so candidates
# have to MOVE between two variable lists, which is the two-list invariant's whole
# reason for existing (tnt_35_multiselect.txt). The argument is still true and still
# governs every list-shaped term in this file; it is simply no longer about captives.
# Full tombstone: the FAMILY B block heading E22 in
# common\scripted_effects\tnt_32_apply.txt.
#
# The filter triggers (tnt_can_cede_title_trigger, tnt_can_grant_claim_trigger,
# tnt_artifact_giftable_trigger) are defined in tnt_40_triggers.txt.
# tnt_nonwar_candidate_trigger was the fourth; it is commented out there with the
# rest of the non-aggression family (tombstone at E25 in tnt_32_apply.txt).
#
# ITEM 19 ADDED SIX LISTS AND SIX FILL EFFECTS, AND ONLY THE WIRING IS
# HERE. FOUR SURVIVE — tnt_list_hostage_p/_r and
# tnt_list_courtier_p/_r — cleared by E4 below and rebuilt by E5 below, in
# the same breath as the nine that shipped. Their BODIES are not in this file:
# integration contract §1.B puts tnt_fill_hostage_p/_r_effect
# and tnt_fill_courtier_p/_r_effect in
# common\scripted_effects\tnt_3a_people.txt, one file one owner, beside the exec
# legs that consume what they build. Their FILTERS are
# tnt_hostage_candidate_trigger and
# tnt_courtier_candidate_trigger, both defined in
# common\scripted_triggers\tnt_42_people_gates.txt.
#
# RETIRED V16, USER ITEM 5 — tnt_list_ward_p/_r, tnt_fill_ward_p/_r_effect and
# tnt_ward_candidate_trigger. The two fill CALLS in E5 are commented out; the two
# clear_variable_list lines in E4 are deliberately KEPT for one cycle (see the note
# at the call site). Reason: the ward term was too abusable on points and the
# hostage term covers the same immersive ground. Full WARD TOMBSTONE:
# common\scripted_effects\tnt_32_apply.txt.
#
# V11 CORRECTION, user item 2: this paragraph used to add "and each fill also
# opens with its term's cheap pair gate (tnt_can_hostage_trigger /
# tnt_can_ward_trigger, retired V16 / tnt_can_courtier_trigger) so that a pair which could
# never use the term pays for no iteration at all". IT DOES NOT. All six fills
# guard on `exists = var:tnt_partner` and nothing else (tnt_3a_people.txt:96-309).
# There is NO correctness consequence, which is why nobody noticed: the show
# gates test their pair gate explicitly and independently
# (tnt_42_people_gates.txt), so an illegal pair's rows are hidden either way.
# The consequence is COST — every window open, every _show transition and every
# post-deal refill runs every_close_family_member x2, every_child x2 and
# every_courtier x2 with the full candidate trigger, even for a pair that can
# never use the term. Adding the pair gate to the six fills is the obvious
# improvement and it is deliberately NOT made in this commit, which is a
# behaviour-preserving one; whoever makes it should make it in all six at once,
# in the shape `if = { limit = { exists = var:tnt_partner
# tnt_can_courtier_trigger = { GIVER = root  RECEIVER = var:tnt_partner } } ... }`.
# Until then this comment describes the code, which is the point.
#
# WHY THE WIRING IS HERE AND NOT AT THE FILL SITES. Exactly the reason the spouse
# fan-out was moved here in build 3: tnt_refill_all_lists_effect is the ONE thing
# every window-open path calls — E1, the tnt_refresh_lists _show state, the AI
# counter-offer path, and the post-apply refill — and a fill parked anywhere else
# leaves some of those paths with an empty list. An empty list is not a harmless
# state for item 19: the six show-gates in tnt_42_people_gates.txt read
# variable_list_size on these very lists, so a missing fill does not show an empty
# picker, it HIDES THE ROW for the rest of the session.
