# PARLEY: THE NEGOTIATING TABLE - THE AI'S OFFER TO THE PLAYER (user item 4, phase AI-1)
#
# 30-V2-DESIGN section 6.3 / 6.4; 43-ai-participation.md section 3.A (rev 2).
# Effects in common/scripted_effects/tnt_37_ai_offer.txt.
# Pulse and GC in common/on_action/tnt_71_ai.txt.
# Embedded widget in gui/event_window_widgets/tnt_offer_summary.gui.
# ASCII only, for the reason given in the effects file's header.
#
# TWO EVENTS, AND THE SPLIT IS THE WHOLE DESIGN.
#
#   .0001  hidden. Composes the package ON THE PLAYER, then either presents it
#          or throws it away. root = THE PLAYER.
#   .0002  the letter the player actually reads. root = THE PLAYER.
#
#=======================================================================
# WHY COMPOSITION CANNOT HAPPEN IN THE ON_ACTION EFFECT - THE ROOT PROBLEM
#=======================================================================
# 43-...md's sketch composes inside the offer event's `immediate`, and it is
# right to. The tempting alternative - compose in the AI's on_action effect
# through `scope:the_player = { tnt_ai_compose_offer_effect = yes }`, check the
# result, and only then fire a single visible event - IS WRONG, and silently so.
#
# A scope change moves `this`, NOT `root`. Inside `scope:player = { ... }` called
# from the AI's on_action, `var:tnt_gold_p` would resolve against the player
# (correct, it is unqualified) but the eight tnt_relmod_* values reach for `root`
# EXPLICITLY - tnt_51_relation_values.txt's opinion row is
# `scope:tnt_p ?= { add = "opinion(root)" }` - and root would be THE AI. Every
# relationship term would then be measured from the wrong side, the composer
# would balance the package against a number that is not the number the player's
# window will show, and nothing would look broken. `X = { trigger_event = Y }`
# re-roots for real (proven twice: culture_on_actions.txt:63-75 into
# bp2_yearly.8050, and fp1_trade_events.txt:1504 into fp1_trade_events.0003), so
# the ONLY place the composer may run is inside an event whose root is the player.
#
# Hence the hidden dispatcher: it buys a root-correct place to compose AND a
# place to abort before the player is ever shown anything (30-V2-DESIGN 6.4
# constraint 3, "if the package is still negative, abort the offer").
#
#=======================================================================
# WHY THE PLAYER IS NEVER INTERRUPTED (30-V2-DESIGN 6.4 constraint 1)
#=======================================================================
# The package is written onto the player, in the same variables the negotiation
# window edits. Firing while a manual negotiation is open would therefore not
# merely annoy - it would DESTROY the player's half-built offer. The guard
# `NOT = { exists = var:tnt_open }` is written three times over: in the candidate
# limit in tnt_ai_offer_try_effect, in that effect's final gate, and in .0001's
# own trigger below. The third one is the one that matters, because a queued
# event is evaluated later than the effect that queued it and the player can open
# the window in between.
#
#=======================================================================
# THE THREE ANSWERS (30-V2-DESIGN 6.2)
#=======================================================================
#   ACCEPT       calls tnt_apply_deal_effect - the same master effect the manual
#                path uses, unchanged, because root is the player and
#                scope:tnt_deal_partner is the other ruler on both paths (that
#                effect's own header says so). Its tooltip is the full,
#                real consequence list, generated by running it in tooltip mode.
#   COUNTER      sets tnt_open = 1 and the negotiation window opens PRE-FILLED
#                with the AI's package, because the package already lives exactly
#                where the window looks. This is the feature that makes the mod
#                feel two-sided.
#   DECLINE      wipes the table.
#
# THE FOURTH ANSWER MOVED OUT - USER ITEM 11. "Decline and hear no more
# embassies" (ten years of silence through tnt_ai_offer_hush_effect) was
# jarring inside a letter the player was already answering, and an option,
# once clicked, cannot be taken back. The opt-out is now the reversible
# decision pair in common/decisions/tnt_85_decisions.txt: an UNTIMED
# var:tnt_envoys_refused that .0001's trigger tests below, plus the same
# ten-year cooldown write the option made. Vanilla's anti-fatigue device is
# still the model (fp1_trade_events.txt:335 sets a permanent opt-out flag for
# humans only, "AI don't need an opt-out") - ours is merely reversible.
########################################################################

namespace = tnt_ai_offer


########################################################################
# tnt_ai_offer.0001 - THE HIDDEN COMPOSER AND DISPATCHER
#
# root = THE PLAYER (re-rooted by `scope:tnt_ai_target = { trigger_event = ... }`
# in tnt_ai_offer_try_effect). scope:tnt_ai_proposer = the AI.
#
# `hidden = yes` shows no window at all (GAME\events\_events.info:38) and takes
# no options; a hidden event whose whole body is an `immediate` that ends in a
# trigger_event is a common vanilla shape (birth.0001, board_games.0011,
# court_maintenance.0003, bp1_yearly.7029 among the first few hundred event files).
#
# No engine cooldown on the hidden composer or either visible event. The former
# 15-day floor also blocked empty drafts, starving the same later proposer on
# successive yearly pulses. Only visible letters spend recipient cooldown;
# tnt_partner/tnt_open protect live work, and aborts clear the table normally.
# Vanilla hidden trigger/immediate guard without cooldown:
# events/secret_events/secrets_events.txt:4714-4770 (secrets.1011).
# Queued/instant events check triggers: events/_events.info:125-129.
########################################################################
tnt_ai_offer.0001 = {
	type = character_event
	hidden = yes

	trigger = {
		is_ai = no
		NOT = { has_game_rule = tnt_ai_offer_rate_off }
		# Only a visible letter spends the recipient's rate budget. Recheck
		# here as well as at PICK: an earlier queued offer may have arrived
		# and been answered before this hidden event gets its turn.
		# trigger_if with a game-rule limit: vanilla common/scripted_triggers/
		# 00_game_rule_triggers.txt:56-57. No event cooldown: see header above.
		trigger_if = {
			limit = { NOT = { has_game_rule = tnt_ai_offer_rate_test } }
			NOT = { exists = var:tnt_ai_offer_cooldown }
		}
		exists = scope:tnt_ai_proposer
		scope:tnt_ai_proposer = { is_alive = yes }

		# NEVER onto a busy player. See the file header.
		NOT = { exists = var:tnt_open }
		NOT = { exists = var:tnt_partner }

		# USER ITEM 11: never onto a player who has barred the door - the
		# decision pair in common/decisions/tnt_85_decisions.txt; the variable
		# is UNTIMED and outlives every cooldown. Tested HERE and not only in
		# the pulse's candidate gates, for the same queued-event race as
		# tnt_open above - and because the pulse's cooldown rows sit inside
		# trigger_if = { NOT = has_game_rule(test-rate) } wrappers, this row is
		# the one that holds at EVERY rate setting. A composition dropped here
		# never writes a proposer lock; that lock starts only in immediate.
		NOT = { exists = var:tnt_envoys_refused }
	}

	immediate = {
		# The trigger has passed, so this is a real composition attempt.
		# The retired 15-day engine floor dropped 13/30 PICKs in the
		# Sarir 1178-1181 run, including all three Tekish attempts.
		# An empty draft now clears the table without blocking its successor.
		tnt_log_dispatch_effect = yes

		# The proposer's own rate remains charged only on actual composition:
		# test 30 days, frequent 1 year, rare 6 years, otherwise 3 years.
		# No proposer lock is paid by a queued event rejected while the
		# player is busy or under a visible-letter cooldown.
		# root = player; the existing scope is the proposing AI.
		# Re-scoped game-rule lookup: vanilla events/birth_events.txt:3313-3317.
		# Event-immediate timed writes: events/court_maintenance_events.txt:318-326.
		scope:tnt_ai_proposer = {
			if = {
				limit = { has_game_rule = tnt_ai_offer_rate_test }
				set_variable = {
					name = tnt_ai_offer_cooldown
					value = 1
					days = 30
				}
			}
			else_if = {
				limit = { has_game_rule = tnt_ai_offer_rate_frequent }
				set_variable = {
					name = tnt_ai_offer_cooldown
					value = 1
					years = 1
				}
			}
			else_if = {
				limit = { has_game_rule = tnt_ai_offer_rate_rare }
				set_variable = {
					name = tnt_ai_offer_cooldown
					value = 1
					years = 6
				}
			}
			else = {
				# normal - build 3's hardcoded number, unchanged.
				set_variable = {
					name = tnt_ai_offer_cooldown
					value = 1
					years = 3
				}
			}
		}

		# Start from a clean table. The trigger above says there is no live
		# negotiation, but residue from an abandoned one is possible and the
		# composer must not add its terms to somebody else's.
		tnt_reset_offer_effect = yes

		# THE ONE LINE THE WHOLE DESIGN RESTS ON. With this set, root is the
		# player and var:tnt_partner is the AI, which is exactly the state the
		# player's own window produces - so all 55 script values, the balance,
		# the breakdown tooltip and tnt_apply_deal_effect all mean what they
		# already mean, with no re-rooting anywhere.
		set_variable = {
			name = tnt_partner
			value = scope:tnt_ai_proposer
		}

		# THE MIRRORS, ON THE LETTER PATH TOO - V14, USER ITEM 3 (deep check).
		# E2b (tnt_30_effects.txt:442) is the mod's SINGLE copy of the government
		# test, and every influence gate in the mod reads the tnt_infl_ok_* pair it
		# writes through tnt_influence_ok_value: the composer's pay pass
		# (tnt_39_autobalance.txt:1991) and sweeten pass (:1739), tnt_items_count_value
		# (tnt_50_values.txt:3895, :3903) and both influence shortfalls
		# (tnt_53_currency_values.txt:701, :720). Every other opener already calls it -
		# tnt_open_window_effect (tnt_30_effects.txt:198), the _show state hook
		# (tnt_22_v2.txt:1300), tnt_20_scripted_guis.txt:1086 and
		# tnt_ai_offer_counter_effect (tnt_37_ai_offer.txt:5406) - but this one did
		# not, and tnt_close_window_effect removes the pair, so every letter after the
		# first started with the mirrors absent. The consequences were both silent:
		# an influence term could never appear in ANY letter, and the letter's
		# headline was computed under different gates from the window's, so the two
		# numbers could disagree across the counter-offer click.
		# IT MUST COME AFTER tnt_partner IS WRITTEN - tnt_30_effects.txt:456-465 reads
		# var:tnt_partner to decide tnt_infl_ok_r.
		tnt_refresh_v2_mirrors_effect = yes

		# THE UNTIMED LETTER MARKER — the stress guard's real gate (V7b defect 1).
		# tnt_ai_offer_arch is timed days = 200 for the GC's sake, but this event
		# can sit unanswered for years by its own design; from day 201 a guard on
		# the ARCH variable silently expires and the accept tooltip grows stress
		# lines for taking the AI's own bargain. This marker has no timer, so it
		# outlives any wait. R-CLEAN: removed on every letter exit —
		# tnt_ai_offer_clear_effect (accept/decline/fail/GC) and
		# tnt_ai_offer_counter_effect (where the letter becomes a manual
		# negotiation and stress correctly applies again).
		set_variable = {
			name = tnt_ai_letter
			value = 1
		}

		# tnt_apply_deal_effect and the two notify effects read the partner as the
		# PERMANENT scope tnt_deal_partner (tnt_32_apply.txt E14/E27/E28), so it is
		# saved here, in the immediate, and not in the accept option: an option's
		# effects are also run in TOOLTIP mode to build its tooltip, and in tooltip
		# mode a save_scope_as does not happen - the master effect's outer
		# `exists = scope:tnt_deal_partner` would fail and the player would hover
		# an empty tooltip. That is defect D5's exact shape.
		# The name is tnt_deal_partner and NOT tnt_p - defect D4: every value in
		# the balance chain opens with R0.4's prologue
		# `var:tnt_partner ?= { save_temporary_scope_as = tnt_p }`, and a permanent
		# scope of the same name makes the engine refuse the temporary one.
		scope:tnt_ai_proposer = { save_scope_as = tnt_deal_partner }

		tnt_ai_compose_offer_effect = yes

		#===============================================================
		# B2, 2026-08-23 - THE DEMAND TAKES A BRANCH OF ITS OWN, ABOVE THE
		# GO / NO-GO, AND THE GO / NO-GO ITSELF IS NOT TOUCHED BY ONE BYTE.
		#===============================================================
		# WHY IT CANNOT USE THE GO / NO-GO. Archetype 21 (tnt_37_ai_offer.txt) is
		# an extortion letter: the player pays coin and receives nothing. The
		# limit below is built to refuse exactly that shape and would refuse it on
		# three independent rows - `tnt_balance_value < 60` (a 200-gold demand
		# lands far above it), `tnt_deal_mod_sum_value >= -35`, and the unpaid-ask
		# OR. That is the limit working correctly, not a bug to exempt away.
		#
		# WHY A BRANCH AND NOT FOUR EXEMPTIONS INSIDE THE LIMIT. That limit is the
		# single most-argued block in the mod; every row in it carries a measured
		# population and an acceptance test, and four arch-21 `trigger_if`s cut
		# through all of them would make each of those arguments conditional on a
		# state none of them was measured in. ONE `if` above it costs nothing and
		# keeps every existing statement literally true.
		#
		# THE DEMAND'S OWN GATE IS THREE ROWS:
		#   1. T53 tnt_can_demand_trigger, RE-CHECKED HERE. The composer tested it
		#      too, but the world moves between the pulse and the event - and a
		#      demand from a man who has since been beaten is the one thing this
		#      feature must never send.
		#   2. var:tnt_gold_p >= 10. tnt_ai_ultimatum_gold_value floors at 10, and
		#      tnt_ai_demand_gold_value clamps to 80% of the purse, so this row is
		#      "the clamp did not eat the whole ask". A player with an empty
		#      treasury is UN-EXTORTABLE, which is correct and will read as "the
		#      feature does not work" - it is an acceptance note, not a defect.
		#   3. NOT = { exists = var:tnt_demand_lock } - the throttle, below.
		#
		# *** THE THROTTLE SHIPS WITH THE FEATURE, NOT AFTER IT. *** This mod has
		# a scar where an AI term became the AI's default offer (the retired
		# tribute), and random_list renormalises over PASSING entries - so for a
		# very weak player A21's gate may be one of the few that passes while A8,
		# A10 and A16 all fail. WEIGHT 6 ALONE DOES NOT COVER THAT CASE. Three
		# independent properties do, and they are named in order of strength:
		#   (1) there is NO RECURRING OBJECT - a demand is one payment and creates
		#       no term of any kind, which is the structural difference from
		#       tribute;
		#   (2) tnt_threat_opinion locks the PAIR for 15 decaying years
		#       (tnt_threat_unspent_trigger, inside T53), so the same neighbour
		#       cannot form a habit;
		#   (3) var:tnt_demand_lock caps the PLAYER's total exposure - a decade at
		#       the default rate - no matter how many bullies border him.
		# HARD ACCEPTANCE BOUND: if COMPOSE|arch=21 exceeds 25% of all COMPOSE in
		# a run, the WEIGHT is wrong, not the concept. The escalation ladder if he
		# wants it rarer still is (a) drop the weight, (b) lengthen this lock,
		# (c) only then a game rule.
		#
		# THE LOCK IS WRITTEN HERE AND NOWHERE ELSE, AT THE EXACT POINT THE LETTER
		# PASSES THE DEMAND'S OWN GATES. Do not spend this lock on a failed
		# composition or an entry-trigger rejection. The ladder below is
		# the proposer rate ladder's four branches,
		# same order, same rule ids, different durations.
		#===============================================================
		if = {
			limit = {
				exists = var:tnt_ai_offer_arch
				var:tnt_ai_offer_arch = 21
			}
			if = {
				limit = {
					tnt_can_demand_trigger = { A = scope:tnt_ai_proposer  B = root }
					exists = var:tnt_gold_p
					var:tnt_gold_p >= 10
					NOT = { exists = var:tnt_demand_lock }
				}

				# THE PLAYER'S EXPOSURE CAP. root is the player here.
				# The rule's fifth setting, `off`, cannot reach this line: at
				# `off` tnt_ai_offer_try_effect skips its whole body and no event
				# is ever queued, so the `else` below means `normal` and nothing
				# else - the same statement the proposer ladder above makes.
				if = {
					limit = { has_game_rule = tnt_ai_offer_rate_test }
					set_variable = {
						name = tnt_demand_lock
						value = 1
						days = 30
					}
				}
				else_if = {
					limit = { has_game_rule = tnt_ai_offer_rate_frequent }
					set_variable = {
						name = tnt_demand_lock
						value = 1
						years = 3
					}
				}
				else_if = {
					limit = { has_game_rule = tnt_ai_offer_rate_rare }
					set_variable = {
						name = tnt_demand_lock
						value = 1
						years = 20
					}
				}
				else = {
					# normal - a decade of quiet after one demand.
					set_variable = {
						name = tnt_demand_lock
						value = 1
						years = 10
					}
				}

				# The same live-marker and dead-man's switch the trade letter
				# gets: the GC in common\on_action\tnt_71_ai.txt reclaims the
				# player on `NOT = { exists = var:tnt_ai_offer_live }`, so a
				# demand left unanswered must carry it too or the state would be
				# reclaimed out from under an open letter.
				set_variable = {
					name = tnt_ai_offer_live
					value = 1
					days = 200
				}

				trigger_event = tnt_ai_offer.0003
			}
			else = {
				# THE DEMAND'S GATE LAPSED BETWEEN THE PULSE AND THIS EVENT, or
				# the player is inside his decade lock. It gets its OWN outcome
				# kind rather than reusing aborted_below_threshold, because
				# arch 21 never reaches the trade limit at all and collapsing the
				# two would make the acceptance test "zero arch=21 aborts"
				# unreadable. The line names which of the three rows refused it.
				tnt_log_demand_abort_effect = yes
				tnt_ai_offer_clear_effect = yes
			}
		}

		#===============================================================
		# THE GO / NO-GO. One check, no loop.
		#
		#   tnt_offer_nonempty_trigger    something is actually on the table.
		#                                 Without this row an archetype whose
		#                                 terms all failed their own guards would
		#                                 send an EMPTY treaty that a merely
		#                                 friendly relationship could still score
		#                                 above zero.
		#   tnt_ai_accept_value > 0       the AI would sign its own offer. This is
		#                                 the mod's single acceptance test, used
		#                                 verbatim, and it is why the AI cannot
		#                                 propose something it would then refuse.
		#                                 Exactly 0 declines (
		#                                 GAME\gui\interaction_templates.gui:3089).
		#   tnt_balance_value < 60        and it is not a rip-off of the PLAYER.
		#                                 tnt_balance_value is the PURE TRADE
		#                                 DELTA - what the AI gains minus what it
		#                                 gives - so it is the honest measure of
		#                                 one-sidedness, where tnt_ai_accept_value
		#                                 also carries relations and the greed
		#                                 floor.
		#                                 THIS IS THE FAIRNESS KNOB. Lower it for
		#                                 a politer AI.
		#
		#                                 V14, USER ITEM 2 - IT WAS 200 AND 200 WAS
		#                                 A DEAD KNOB. It was set when the mod's
		#                                 currency was "100 points is a year of the
		#                                 AI's income" and was documented here as
		#                                 "about two years of unearned surplus".
		#                                 Under the v3-iteration-2 recalibration a
		#                                 point is 10-15 gold
		#                                 (tnt_50_values.txt:339-352), so 200 points
		#                                 is 2,000-3,000 gold of pure surplus taken
		#                                 off the player in one letter - which is the
		#                                 exact shape of the trash he reported. 60 is
		#                                 high_positive_ai_value + very_low on
		#                                 vanilla's own ladder
		#                                 (GAME\common\script_values\00_ai_values.txt
		#                                 :22-27) and is about 600-900 gold: room for
		#                                 a hostility premium, no room for a heist.
		#                                 COSTS NOTHING MEASURED: the largest
		#                                 tnt_balance_value in the whole 2026-08-16
		#                                 run was +13, so no letter of that run
		#                                 changes verdict on this row alone.
		#
		#                                 THIS KNOB IS NOT THE PLAYER'S SIDE OF THE
		#                                 LEDGER. It caps the AI's surplus; it does
		#                                 not ask whether the player wants the deal.
		#                                 Vanilla's marriage interaction asks that
		#                                 question directly - it is the one
		#                                 interaction in the game that gates the AI's
		#                                 SENDING on the RECIPIENT's ledger, and PDX
		#                                 says so in the file's opening comment,
		#                                 GAME\common\character_interactions\
		#                                 00_marriage_interactions.txt:3-11 - and this
		#                                 mod cannot, because it has no player-side
		#                                 aggregate anywhere in common\script_values.
		#                                 THE SUBSTITUTE IS A PRICE: a mismatched
		#                                 marriage now costs the AI 40-115 points to
		#                                 propose (tnt_52_marriage_values.txt value 8,
		#                                 V14 user item 4), so it can no longer clear
		#                                 this gate on pocket change. In a one-sided
		#                                 ledger "I refuse" and "you must pay me what
		#                                 you do not have" are the same statement, and
		#                                 vanilla itself reaches its verdict with a
		#                                 number (-5000) rather than a gate.
		#
		# All rows are named-value-or-trigger against a literal, never variable
		# against variable (Law R7).
		#
		# B2, 2026-08-23: THE ONLY CHANGE TO THIS BLOCK IS THE KEYWORD `else_if`.
		# Not one row of the limit moved, and no arch-21 exemption was cut into
		# it. Archetype 21 is answered whole by the branch above and can never
		# reach here, which is what keeps every measured population and every
		# acceptance test in the 270 lines below literally true.
		#===============================================================
		else_if = {
			limit = {
				# V17, USER ITEM 3 - THE ARCHETYPE MUST EXIST AT ALL, ASSERTED HERE AS
				# WELL AS AT THE SOURCE. The belt is in the composer
				# (tnt_37_ai_offer.txt, the `if = { limit = { exists =
				# var:tnt_ai_offer_arch } tnt_ai_offer_settle_effect = yes }` at the very
				# end of tnt_ai_compose_offer_effect); this is the brace. With no arch
				# index there is no prose branch either, so the letter ships under
				# tnt_ai_offer_desc_generic as three demands and nothing offered - which
				# is exactly what the user photographed in temp/screen4.png.
				# WHY BOTH: the row below it, tnt_offer_nonempty_trigger, counts the
				# three currency variables the settle itself writes, so it could never
				# refuse an empty draw on its own. Asserting the index HERE means a
				# future composer edit cannot silently reopen the hole. Every live entry
				# writes the index, so this refuses nothing that actually drew.
				# Proven in-mod form: this same file's own desc branches read
				# `var:tnt_ai_offer_arch = N` eleven times over.
				exists = var:tnt_ai_offer_arch
				tnt_offer_nonempty_trigger = yes
				tnt_ai_accept_value > 0
				tnt_balance_value < 60
				# =========================================================
				# V24, LEDGER OPTION B - REFUSE A MARRIAGE VANILLA ITSELF
				# WOULD DECLINE. A16 pair whose own net (offer_p - offer_r)
				# is negative is a match vanilla's arrange-marriage AI
				# refuses outright (base = 0, accepts only above); composing
				# it anyway is what produced "marry my kinsman AND pay me
				# 478 gold" - the settle billed the PLAYER for the
				# proposer's own reluctance. Measured 08-21: kills 21 of 23
				# A16 composes; the surviving 2 are exactly the two where
				# the AI paid the player. Arch-gated so no other archetype
				# pays this test; trigger_else keeps every non-marriage
				# letter untouched. The value and its full argument:
				# tnt_52_marriage_values.txt, above the preview trio.
				# The pair does not exist at entry-trigger time, so this
				# cannot move into the entry. Failure spends only the proposer's
				# own attempt, not a recipient or visible-letter cooldown.
				# =========================================================
				trigger_if = {
					limit = { var:tnt_ai_offer_arch = 16 }
					tnt_marriage_net_r_value >= 0
				}
				trigger_else = { always = yes }
				# =========================================================
				# V17, USER ITEM 2 - THE STANDING FLOOR, AND IT IS THE ONE

			# without AGOT, which is the mod's standing rule. Both flags

			# R-CLEAN needs no removal path for either. Both use the mod's
			# own tnt_ prefix rather than vanilla's `player_declined_marriage`,
			# so this mod neither reads nor writes vanilla's flag and cannot
			# interfere with vanilla's own marriage AI.
			#
			# Inside hidden_effect, so neither write generates a tooltip
			# line in the option's tooltip pass (defect D5's shape), and a
			# decline stays exactly as costless to the player as its header
			# above promises: this silences the SENDER, it does not punish
			# the player.
			# ==========================================================

			# (1) THE RULER, five years. Vanilla:
			#     GAME\common\character_interactions\00_marriage_interactions.txt
			#     :740-745 writes `player_declined_marriage`, and
			#     GAME\common\scripted_modifiers\00_marriage_scripted_modifiers.txt
			#     :2345-2350 spends it as `add = -5000` under the header
			#     "Secondary actor has already been refused by the player".
			# READ BY tnt_ai_worth_hearing_trigger (tnt_41_gates.txt), so it
			# silences ONLY the two STANDING archetypes, A16 and A3 - which is
			# vanilla's own scoping, where the flag suppresses marriage and
			# nothing else. Fealty, courtiers and land are untouched.
			# scope:tnt_deal_partner and not scope:tnt_ai_proposer: the former
			# is saved in .0001's own immediate and is the name every apply
			# effect in this mod already expects; :307-309 records that the two
			# names are one character.
			scope:tnt_deal_partner ?= {
				add_character_flag = {
					flag = tnt_declined_by_player
					years = 5
				}
			}

			# (2) THE PERSON, five years - the finer grain, and the one that is
			# the literal port. Vanilla writes its flag on scope:secondary_actor,
			# i.e. THE OFFERED SPOUSE, not on the ruler. tnt_wed_list holds the
			# PLAYER-side spouse of each committed pair and carries the AI-side
			# one as var:tnt_wed_partner (tnt_34_marriage.txt, tnt_wed_add_pair_
			# effect), so the AI-side halves are exactly what is flagged here.
			# Read back by BOTH of arch16's candidate draws in
			# tnt_37_ai_offer.txt, so a person the player has already turned down
			# is not put in front of him again even if the ruler-level flag has
			# expired or the letter came from somebody else.
			# has_variable_list FIRST - variable_list_size on a never-created
			# list is an engine error, not a zero (tnt_34_marriage.txt:658-664).
			# `every_in_list` over a variable list with `var:x ?= { ... }` is this
			# mod's shipped idiom (tnt_52_marriage_values.txt, the pair loops).
			if = {
				limit = {
					has_variable_list = tnt_wed_list
					variable_list_size = { name = tnt_wed_list  value > 0 }
				}
				every_in_list = {
					variable = tnt_wed_list
					var:tnt_wed_partner ?= {
						add_character_flag = {
							flag = tnt_declined_marriage
							years = 5
						}
					}
				}
			}

			# LAST, because it wipes the list the block above reads.
			tnt_ai_offer_clear_effect = yes
		}

		ai_chance = {
			base = 50
		}
	}

	# USER ITEM 11: the fourth option - "decline and hear no more embassies",
	# ten years of silence through tnt_ai_offer_hush_effect - lived here and is
	# gone. See the file header; the opt-out is now the reversible decision
	# pair in common/decisions/tnt_85_decisions.txt. Its two loc keys
	# (tnt_ai_offer_opt_hush / tnt_ai_offer_hush_tt) stay in both .yml files as
	# recorded orphans, per the mod's own policy (tnt_40_triggers.txt, the
	# tnt_err_vassal_invalid precedent: an unreferenced key costs nothing, an
	# undefined one prints raw on screen).

	#===================================================================
	# The safety net for the case the engine DOES run it (_events.info:125-129
	# warns it typically does not for on_action-selected events, and this event
	# is queued by trigger_event rather than selected, so it can). The real
	# protection against a stranded package is the GC in tnt_71_ai.txt.
	#===================================================================
	on_trigger_fail = {
		tnt_ai_offer_clear_effect = yes
	}
}

# tnt_ai_offer.0003 - THE DEMAND      (B2, 2026-08-23)
#
# root = THE PLAYER. scope:tnt_ai_proposer / scope:tnt_deal_partner = the AI.
# Reached only from .0001's arch-21 branch, above the trade go/no-go.
#
#=======================================================================
# WHY THIS IS A SEPARATE EVENT AND NOT A THIRD OPTION ON .0002
#=======================================================================
# Three reasons, and each one alone would be sufficient.
#
# 1. THE COUNTER-OFFER OPTION WOULD GUT THE FEATURE. On .0002 the player can
#    press "Open the negotiating table", trim the demanded gold to 20, press
#    Propose - and the AI signs, because its ledger has no fear row in this
#    direction (that asymmetry is the whole of CLAUDE.md section 3's «threat is
#    a player-only multiplier» paragraph, and it is still true). A demand that
#    can be haggled down to nothing is not a demand.
# 2. .0002's OWN HEADER FORBIDS THE CHEAP FIX. "An option's trigger is not a
#    filter, it is a kill switch with no error message" - EVENT_OPTIONS_SHOWN_
#    HIDE_UNAVAILABLE = 4 and this event has three options, so a dead option
#    stays on screen pixel-identical to a live one. Filtering .0002's three
#    options by archetype would put two dead buttons on every demand.
# 3. .0002's RECORDED RULING MUST STAY STANDING. "DECLINE. No opinion penalty
#    and no toast: refusing an embassy is not an insult." A demand is not an
#    embassy, and refusing one DOES cost prestige - keeping the two in different
#    events is what lets both statements stay literally true. THE TWO HEADERS
#    CROSS-REFERENCE EACH OTHER ON PURPOSE: a future round that "harmonises"
#    them will delete this feature's teeth.
#
#=======================================================================
# NO EMBEDDED BALANCE WIDGET, DELIBERATELY
#=======================================================================
# tnt_offer_summary's headline answers "would the AI sign this", which on a
# demand is meaningless - he wrote it. The sum is named in the prose instead.
# FALLBACK if the prose ever reads thin: one line,
#   widget = { gui = "tnt_offer_summary" container = "custom_widgets_container" }
# exactly as .0002 carries it.
#
#=======================================================================
# THE TWO ANSWERS, BOTH PRICED - AND THIS IS A FIRST FOR THE MOD
#=======================================================================
# Nothing in Parley has ever charged the player for the option he did NOT
# choose. It is done here by explicit user decision, and the price is vanilla's
# own grammar rather than an invention: GAME\events\lifestyles\
# subject_extortion_events.txt ships five "Back out" options, each charging
# prestige (:75, :135, :195, :244, :304), and pays successful extortion in dread
# (:43, :124, :172, :232, :280). The party who has a scene made in his hall and
# then does neither of the two things a scene demands is the one who drops it.
#
#   PAY     -> the gold moves through tnt_apply_deal_effect, the demander gains
#              +10 dread, and the memory is written. tnt_deal_from_letter is
#              saved so the STRESS LAYER STAYS SUPPRESSED: being extorted is not
#              a treaty you chose (tnt_3c_stress.txt:261).
#   REFUSE  -> he loses 10 dread (a threat that is refused is a threat that has
#              been measured), the player loses 75 or 150 prestige by the size
#              of the pressure - AND NOTHING AT ALL if T53 no longer passes at
#              click time, which is the out-grown waiver that makes this a game
#              rather than a tax.
#
# THE OPINION MEMORY IS WRITTEN ON BOTH BRANCHES - he tried, and that is what is
# remembered - and its DIRECTION is load-bearing. See tnt_demand_refused_effect
# in common\scripted_effects\tnt_37_ai_offer.txt.
#
# REFUSE CARRIES NO TRIGGER AT ALL, exactly as .0002's Decline does not, so the
# letter can never become unanswerable no matter how long it is left lying
# there. PAY carries only session identity in its option trigger (the player may
# have opened a negotiation with somebody else in the meantime). The complete
# package, including the player's purse, is checked in its click effect instead:
# if the gold is gone, the explicit stale branch moves nothing, explains the
# lapse and clears the demand rather than leaving a silent dead button.
########################################################################
tnt_ai_offer.0003 = {
	type = character_event
	title = tnt_ai_demand_title
	# `war` is a real event theme: GAME\common\event_themes\00_event_themes.txt:532.
	theme = war

	desc = {
		# THE MOTIVE LINE, same shape and same Law R7/R13 discipline as .0002's:
		# exists first, then the variable against a literal. Only two codes can
		# reach here - 14 (the host is mustered, A21's own) and 6 (the empty
		# chest, reused from the sell-side archetypes at zero loc cost) - and a
		# missing variable falls through to the blank key exactly as it does on
		# the trade letter.
		first_valid = {
			triggered_desc = {
				trigger = {
					exists = var:tnt_ai_goal
					var:tnt_ai_goal = 14
				}
				desc = tnt_ai_goal_might
			}
			triggered_desc = {
				trigger = {
					exists = var:tnt_ai_goal
					var:tnt_ai_goal = 6
				}
				desc = tnt_ai_goal_poor
			}
			desc = tnt_ai_goal_blank
		}
		# ONE archetype, so no branch: the letter is only ever sent for arch 21.
		# TWO SIBLING PLAIN `desc =` LINES IN ONE desc BLOCK CONCATENATE - vanilla's
		# own shape, GAME\events\birth_events.txt (birth.2002.start + birth.2002.end,
		# and birth.3041.start.desc + birth.3041.end). .0002 does the same thing with
		# one first_valid and one trailing desc.
		desc = tnt_ai_demand_desc_a21
		desc = tnt_ai_demand_desc_outro
	}

	# `anger` is a real portrait animation, 9 sites under GAME\events, first at
	# bp1_dan_events.txt:1967.
	left_portrait = {
		character = scope:tnt_deal_partner
		animation = anger
	}
	right_portrait = {
		character = root
		animation = idle
	}

	trigger = {
		is_ai = no
		exists = var:tnt_partner
		exists = scope:tnt_deal_partner
		scope:tnt_deal_partner = { is_alive = yes }

		# The window must still be closed - the player may have opened a manual
		# negotiation between .0001's immediate and this event being presented.
		NOT = { exists = var:tnt_open }

		# And the table must still be THIS demander's. Shipped shape for
		# comparing an object variable with a scope (tnt_70_on_actions.txt:76),
		# never a bare variable-to-variable comparison (Law R7).
		var:tnt_partner ?= { this = scope:tnt_deal_partner }
	}

	#===================================================================
	# PAY. On the valid preflight branch tnt_apply_deal_effect stays visible, so
	# the player reads the complete real consequence list. A stale branch does
	# not render or execute the master; it shows tnt_err_deal_changed and then
	# clears the impossible demand behind hidden feedback/telemetry effects.
	#===================================================================
	immediate = {
		# Same recipient rate as trade letters; the demand's own lock is separate.
		tnt_ai_offer_recipient_cooldown_effect = yes
	}

	option = {
		name = tnt_ai_demand_opt_pay

		trigger = {
			exists = var:tnt_partner
			exists = scope:tnt_deal_partner
			scope:tnt_deal_partner = { is_alive = yes }
			NOT = { exists = var:tnt_open }
			var:tnt_partner ?= { this = scope:tnt_deal_partner }

			# No package-validity row belongs here. Keeping Pay clickable is what
			# lets the click-time preflight report an emptied, unaffordable or
			# otherwise stale demand and then clear the dead letter cleanly.
		}

		if = {
			limit = {
				tnt_deal_preflight_trigger = {
					PLAYER = root
					PARTNER = scope:tnt_deal_partner
				}
			}

			custom_tooltip = tnt_ai_demand_pay_tt

		# BEFORE the consequences, so the line records the ask as it stood.
			hidden_effect = { tnt_log_demandend_paid_effect = yes }

		# THE STRESS GUARD. Being extorted is not a treaty you chose, so the
		# stress layer stays suppressed exactly as it is on .0002's accept -
		# and for the same reason it must NOT be inside hidden_effect: the
		# apply effect renders in tooltip mode for this option, and a save
		# inside hidden_effect would be absent during that pass, advertising
		# stress this path never charges. (tnt_3c_stress.txt:261;
		# save_scope_value_as on a visible option effect path is vanilla's shape,
		# GAME\events\decisions_events\pledge_loyalty_to_liege_events.txt:200.)
			save_scope_value_as = { name = tnt_deal_from_letter  value = 1 }

			tnt_apply_deal_effect = yes

		# +10 dread on him and the 15-year memory on the player toward him.
		# Top level, not hidden: the player must read what paying buys him.
			tnt_demand_paid_effect = yes

			hidden_effect = {
				tnt_log_verdict_accept_effect = yes
				tnt_ai_offer_clear_effect = yes
			}
		}
		else = {
			custom_tooltip = tnt_err_deal_changed
			hidden_effect = {
				tnt_notify_stale_deal_effect = yes
				tnt_log_preflight_fail_effect = yes
				tnt_ai_offer_clear_effect = yes
			}
		}

		# Inert today (`is_ai = no` in the trigger), and kept for the same reason
		# .0002's three are: it is what would let an AI recipient reuse this
		# event unchanged. `ai_boldness` inside ai_value_modifier is verbatim
		# vanilla - GAME\events\blackmail_events.txt:114-117, which is the same
		# question this letter asks.
		ai_chance = {
			base = 50
			ai_value_modifier = {
				ai_boldness = -0.5
			}
		}
	}

	#===================================================================
	# REFUSE. NO TRIGGER - the letter must always stay answerable.
	#===================================================================
	option = {
		name = tnt_ai_demand_opt_refuse

		# THE TOOLTIP BRANCHES WITH THE PRICE, because a waived prestige rung
		# that still promised a loss would be the "positive misstatement at the
		# control" defect this project has already closed once (CLAUDE.md
		# section 3, tnt_item_threat_desc). The limit is the SAME call the
		# effect makes, one statement later and in the same world state.
		# custom_tooltip as a bare effect statement is vanilla's own shape:
		# GAME\events\birth_events.txt:234 and :237.
		if = {
			limit = {
				exists = scope:tnt_deal_partner
				tnt_can_demand_trigger = { A = scope:tnt_deal_partner  B = root }
			}
			custom_tooltip = tnt_ai_demand_refuse_tt
		}
		else = {
			custom_tooltip = tnt_ai_demand_refuse_free_tt
		}

		# *** THIS CALL MUST STAY ABOVE tnt_demand_refused_effect. ***
		# That effect writes tnt_threat_opinion, and T53's last row is
		# tnt_threat_unspent_trigger, which tests for exactly that modifier -
		# so a log line emitted afterwards would always report free=1.
		hidden_effect = { tnt_log_demandend_refused_effect = yes }

		# Top level, not hidden: add_prestige and add_dread render their own
		# lines and the player is entitled to read the price before he clicks.
		tnt_demand_refused_effect = yes

		hidden_effect = {
			tnt_log_verdict_decline_effect = yes
			tnt_ai_offer_clear_effect = yes
		}

		ai_chance = {
			base = 50
			ai_value_modifier = {
				ai_boldness = 0.5
			}
		}
	}

	on_trigger_fail = {
		tnt_ai_offer_clear_effect = yes
	}
}
