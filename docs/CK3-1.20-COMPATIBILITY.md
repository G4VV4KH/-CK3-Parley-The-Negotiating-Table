# Parley: CK3 1.20 compatibility

## CK3 1.20.0.3 review — 2026-10-01

Compared the installed patch with the retained 1.20.0.2 script baseline: 11 of 3,731 files changed across `common`, `events`, `gui` and `data_binding`; no files were added or removed in those directories with the reviewed script extensions. None of the changed files replaces a Parley file, and no changed scripted helper is reachable in the bounded native-helper token review. The patch removes a vanilla elective-candidate title-grant restriction, adjusts pilgrimage treasury handling, fixes Rite/reformation and Iberian-struggle setup, corrects a landless VIP-contract scope and delays a Latin Empire event. Parley neither overrides those changed definitions nor references the removed `election_candidate_unfair` identifier. Its county-transfer gates and marriage/vassalization helpers remain valid.

The current native-contract audit resolves all 399 active external plain keys and all 15 suffix-bounded scripted helpers, with no helper-parameter or typed-government mismatch. The autobalance, 1.20 compatibility, AI-world native-scope, marriage-verdict and AGOT-suspension suites report 42 passed and one skipped historical-RC9 delta check. The active AGOT-exclusion checks pass. Parley remains **1.1.0**, and `supported_version="1.20.*"` already covers the patch. No runtime file or release archive changed.

**Evidence boundary:** this patch was checked by upstream-script comparison and static regression models; no new 1.20.0.3 engine run was performed. The latest in-game checks remain on 1.20.0.2. Binary-engine behavior, multiplayer and long campaigns are not established by these source checks. External audit evidence is retained under `verification-evidence/ck3-1.20.0.3-2026-10-01/` in the release workspace.

Uppercase macro arguments and dynamic scope paths are excluded from that lexical key count. Token presence does not establish scope typing or prove that every native identifier is unchanged semantically.

The bounded dependency audit found two direct native effect calls and five reachable native effects; no further missing-scope requirement was found in their effects, marriage/artifact/title triggers or values.

The existing 14-test autobalance suite, rule conformance, the 75-check AI dispatcher policy model and the visible-letter rate contract pass. ## RC7 rejection and RC8 focused verification

The subsequent RC7 natural AI-world run reached strategic submission and called
`offer_vassalization_interaction_effect` without `scope:puppet_or_actor`. CK3
1.20 uses that alias for the new liege, the became-vassal opinion target and the
struggle catalyst. The engine reported undefined/unset targets and a null
`change_liege` target. This is a Parley caller defect, not an optional AGOT
diagnostic. The archived witness is
`verification-evidence/crozier-2026-09-30/engine/rc7-final/logs/error.log`
(SHA-256 `4BFB615FEC3C8D44BB28533488841BFA0430AE2A174E83E356B72B72656865E1`).

RC8 refreshes the alias from `scope:actor` inside the single
`tnt_ai_world_apply_vassal_effect` seam shared by paid fealty and coerced
submission. The recipient remains the ruler who submits; all four existing
obligation options remain boolean `no`. Binding the alias at this seam also
replaces a stale proxy alias and does not depend on the caller's current scope.
No price, acceptance threshold, AI frequency or MCA runtime changed for RC8.
Source/model evidence is recorded in
`verification-evidence/crozier-2026-09-30/parley-ai-world-native-scope-fix.json`.

RC8's separate AI-scope harness passed all 12 engine assertions. Two actual
production-seam calls under a third-character root verified absent and stale
aliases, the named actor as the new liege, became-vassal opinion and independent
actor ownership. The run produced no native alias, null-target or type failure.
Its 11 nonshipping fixture-format warnings (nine wrapper escaping and two BOM
warnings) remain recorded separately; assertion success does not make that log
empty. Evidence is under `engine/rc8-ai-harness/` in the dated release evidence.

The no-harness RC8 playset then ran the original Saladin baseline from
1 October 1178 to 24 January 1179. Amr of Asir naturally offered fealty for
743 gold at acceptance +2. Acceptance executed the treaty: player gold changed
from 1,318 to 575 and Asir joined the realm. No opposing currency payment or
prestige payment was included. The repaired AI-world scope failure did not
recur, and no MCA animation-state diagnostic appeared. This short run does not
exercise every AI policy branch or establish that every offer reaches +1.

The clean-playset log retains 40 classified startup diagnostics and seven
additional native records. All seven reproduce exactly after removing only
wall-clock timestamps in an all-mods-off run of the same original save, through
24 May 1179: one revoke-title hook diagnostic and six birth/real_father records.
This establishes reproduction without active Parley/MCA, not the ultimate cause
of that saved state. Evidence is under `engine/rc8-clean/` and
`engine/vanilla-same-save-control/`. No globally clean-log claim is made.

RC6's 34 assertions and RC7's MCA UI results remain scoped to their checked
bytes and semantics. RC8's sole runtime change from RC7 is the AI-world alias
binding; these separate records jointly support the focused release check,
without treating rejected RC7 as a passing whole candidate.
